📋 一、项目概述

TREK 是开发者 mauriceboe 打造的一款自托管（self-hosted）旅行 / 行程规划应用。它的定位非常清晰——做一个"数据完全归你自己的 Wanderlog / TripIt"：你把行程、地图、预算、打包清单、游记、证件全部放在自己服务器上，多人实时协作，还能像原生 App 一样装到手机里离线使用。

Google Trips 已死，TripIt 重在整理订单而非规划，Wanderlog 又把你的行程锁在云端。TREK 把"规划 + 管理 + 协作 + 记录"四件事一次性做齐，而且全部跑在你自己的 Docker 里。

项目近期登上 GitHub Trending 与 Trendshift 榜单，被 Reddit r/selfhosted 社区广泛讨论，并在 v3.0.0 引入旅行游记（Journey）插件、把 Mapbox GL 作为与 Leaflet 并列的一等公民渲染引擎之后迎来跨越式更新，是 self-hosted 领域少见的"完成度接近商业产品"的旅行类应用。

🏗️ 二、技术架构

TREK 走的是一条"单镜像 + 单文件数据库"的极简自托管路线：前端 React SPA 与后端 Node 服务打包进同一个 Docker 镜像，数据落在 SQLite，无需额外部署 Postgres / Redis / 消息队列。这种架构让部署成本极低，同时通过 WebSocket 实现了不简单的实时协作。

🔐 安全设计亮点

生产级 Compose 示例体现了较强的安全意识：容器以 read_only: true 运行、cap_drop: ALL 仅保留必要的 CHOWN/SETUID/SETGID、tmpfs 挂载 /tmp 带 noexec,nosuid。敏感凭据（第三方 API Key、MFA、SMTP、OIDC Secret）通过 ENCRYPTION_KEY 静态加密存储，并提供密钥轮换脚本（migrate-encryption.ts，变更前自动生成带时间戳的数据库备份）。

🚀 30 秒启动

ENCRYPTION_KEY=$(openssl rand -hex 32) docker run -d -p 3000:3000 \
  -e ENCRYPTION_KEY=$ENCRYPTION_KEY \
  -v ./data:/app/data -v ./uploads:/app/uploads mauriceboe/trek

首次启动自动播种管理员账号；反代方面同时给出 Nginx 与 Caddy 配置，并特别提醒 WebSocket 必须在 /ws 支持升级。

💡 三、核心创新点

🧩 模块化插件（Addon）体系
Lists / Budget / Documents / Collab / Vacay / Atlas / Journey / Naver Import / MCP 九大插件，管理员按需开关。功能不再"全家桶"，小团队可只开核心，进阶玩家再解锁 Atlas 世界地图、Vacay 假期日历。
🤖 AI 原生：内置 MCP Server
这是同类项目里少见的配置——TREK 自带 OAuth 2.1 鉴权的 MCP 服务端，暴露 150+ 工具与 30 资源、27 个细粒度 scope。AI 助手可直接帮你建行程、排日程、生成打包清单、管理预算、标记已访问国家，内置 trip-summary / packing-list / budget-overview 等提示词。
🗺️ 双地图引擎 + 3D 可视化
Leaflet 与 Mapbox GL 并列一等公民。Mapbox 渲染 3D 建筑、地形、照片标记、聚合与路线，让"行程可视化"达到商业级表现力，而非平面的点位散点图。
👥 实时多人协作
WebSocket 让多人编辑同一行程即时同步，配合角色权限、一次性 / 可复用邀请链接（可设过期）、群聊、共享笔记、投票、每日签到，把"一群人凑一个旅行计划"这件事工程化。
📱 真正的离线 PWA
Workbox 缓存瓦片、API、上传文件，全屏独立窗口、主题化状态栏、启动屏、安全区适配——装到手机后体验接近原生 App，断网也能查看行程。
🔒 企业级身份与隐私
OIDC SSO（Google/Apple/Authentik/Keycloak）+ TOTP 2FA + SSO-only 模式；ALLOW_INTERNAL_NETWORK 受控放行内网（如访问局域网 Immich）；默认禁止出向访问私网 IP，防止 SSRF。
🎒 旅行管理闭环
预订（机票/住宿/餐厅，含确认号与附件）、多币种预算（饼图、按人按天分摊）、打包清单（模板/分配/进度，可选行李称重）、文档管理（≤50MB）、整行程 PDF 导出——把"规划→执行→归档"打通。
✈️ Journey 游记 + Atlas 足迹
v3.0 引入杂志风游记（条目、照片、心情，可对接 Immich/Synology）；Atlas 用"液态玻璃"UI 绘制已访问国家世界地图、心愿单、旅行统计与连续打卡——既是规划器也是回忆录。
最值得玩味的是 MCP 的接入思路：TREK 不是简单地"加个 AI 聊天框"，而是把整套旅行数据通过受 OAuth 保护的标准化协议交给 AI 助手。这意味着你的行程可以成为任意支持 MCP 的 AI 客户端的一等数据源——在 AI Agent 时代，这种"可被 Agent 调用的自托管服务"的设计前瞻性很强。

⚖️ 六、优势与局限

✅ 优势

  • 完成度极高：从规划、管理、协作、预算到游记足迹，一条龙且都做到了可用水平，不像早期开源项目"半成品"。
  • 部署极简：单镜像 + SQLite，1 行 Docker 或 Helm 一键起，无 Postgres/Redis 依赖，迁移与备份友好。
  • AI 前瞻性：内置 OAuth 2.1 保护的 MCP Server，在 Agent 时代把"自托管数据 + AI 自动化"打通，同类罕见。
  • 安全默认：只读容器、最小权限、密钥加密、SSRF 防护、密钥轮换脚本，生产级意识到位。
  • 本地化优秀：15 种语言含中文 / 繁中 / 阿拉伯语（RTL），暗色主题与 PWA 体验接近原生。

⚠️ 局限

  • 单人维护：作者为个人开发者，长期可持续性与商业支持存在不确定性（社区已开始接入 Dokploy/Railway/Zeabur 等分发渠道）。
  • SQLite 上限：单文件数据库对超大规模多租户或高并发写入场景并非最优，重度企业部署可能需要评估。
  • 地图 / Places 依赖：Mapbox GL 与 Google Places 需自备 API Key；免 Key 路径依赖 OSM，体验略降。
  • AGPL v3 约束：若二次开发后作为网络服务对外提供，须同样开源，商业闭源 SaaS 化受限。
  • 生态尚浅：插件 / 主题等扩展生态刚起步，第三方集成主要靠官方推进。

📅 七、版本演进与生态

  • v3.0.0（重大更新）：被作者称为"史上最大版本"，引入 Journey 旅行游记插件，并将 Mapbox GL 提升为与 Leaflet 并列的一等渲染引擎。
  • AI / MCP：后续版本加入内置 MCP Server（OAuth 2.1，150+ 工具），让 AI 助手可安全操作行程数据。
  • 分发渠道：已入选 Dokploy Templates（#771）、Railway 一键部署、Zeabur、Hostinger VPS 一键安装等，自托管分发矩阵逐步成型。
  • 社区：活跃的 Discussions 与 Wiki，作者在 r/selfhosted 直接与用户互动，迭代节奏较快。
