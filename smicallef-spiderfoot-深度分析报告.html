一、项目概述

SpiderFoot 是由澳大利亚安全专家 Steve Micallef（@smicallef）个人主导开发的开源情报（Open Source Intelligence, OSINT）自动化工具。它能针对 IP 地址、域名、邮箱、用户名、子网段、比特币地址、哈希等多种目标类型，自动从互联网公开渠道采集、关联并可视化情报。

项目最早可追溯到约 20 年前用 C# 写的原型版本，现行的 Python 版本诞生于 2012 年 3 月 4 日。到 2022 年 1 月，SpiderFoot 迎来 10 周年，作者撰写了《Lessons learned from my 10 year open source project》回顾这一漫长维护历程。它长期被收录进 Kali Linux 渗透测试发行版，并通过 SourceForge 分发，是安全社区公认的"瑞士军刀"级 OSINT 工具。

定位

一句话概括：给一个目标，自动跑遍全网公开数据源，把碎片化情报串成一张关系网。

"SpiderFoot automates OSINT for threat intelligence and mapping your attack surface." —— 官方仓库简介

二、技术架构

SpiderFoot 采用经典的 目标输入 → 模块分发 → 数据源查询 → 关联引擎 → 结果聚合 流水线架构，核心由扫描引擎（Scan Engine）、模块系统（Modules）和数据库（SQLite/SQL）三部分构成。Web UI 与 CLI 共用同一套扫描引擎。

[ 目标输入 Target ]
    │   (IP / 域名 / 邮箱 / 用户名 / 哈希 / 比特币地址 ...)
    ▼
[ 扫描引擎 Scan Engine ] ──► 决定扫描类型与模块调度
    │   ◆ Passive 被动（不接触目标）
    │   ◆ Active 主动（直接探测目标）
    │   ◆ Footprint 全量
    ▼
[ 模块分发 Module Dispatcher ] ──► 200+ 插件并行查询
    │   Shodan · Censys · VirusTotal · HaveIBeenPwned
    │   WHOIS · DNS · crt.sh · Nmap · Nuclei ...
    ▼
[ 关联引擎 Correlation Engine ] ──► 触发级联（发现邮箱→查泄露库）
    ▼
[ 结果聚合 Result Store (SQLite) ] ──► Web UI / CLI / JSON 报告

核心组件

  • 扫描引擎（Scan Engine）：负责任务调度、模块生命周期管理与并发控制，将目标分发到选中的模块。
  • 模块系统（Modules）：200+ 个独立插件，每个对应一个数据源或本地工具，可按需勾选，按 Free / Tiered / Commercial / Internal / Tool 分类。
  • 关联引擎（Correlation Engine）：核心创新点。一个模块产出的数据可触发其他模块——例如扫到一个邮箱，会自动去 HaveIBeenPwned 查泄露、去 Gravatar 查头像、去 PGP 服务器查公钥，形成关系图谱。
  • 数据存储：默认 SQLite，结果结构化入库，支持导出与可视化。
  • 接口层：Web GUI（浏览器操作，适合非技术用户）与 CLI（脚本化、CI 集成）双模式。

扫描类型

类型行为典型场景
Passive 被动仅查询第三方数据源，不与目标直接交互，"不留痕迹"隐蔽侦察、合规严格的场景
Active 主动直接探测目标系统（端口扫描、抓取网页等）授权渗透测试、红队
Footprint 全量尽可能多地收集一切可获取信息攻击面测绘、深度尽调

三、核心创新点

🔄 模块级联与数据关联
不是简单堆砌数据源，而是让模块之间互相触发。一处发现（如一个邮箱）可自动展开成一张覆盖泄露、社交、PGP、地理位置的关系网——这是与"单点查询工具"的本质区别。
🧩 200+ 数据源的统一抽象
把 Shodan、Censys、VirusTotal、HaveIBeenPwned、WHOIS、crt.sh 等上百个异构 API、黑名单、本地工具，统一封装成可插拔模块，用户只需勾选，无需逐一对接。
🎯 被动 / 主动 / 全量三模式
同一目标、同一工具，可按合规与隐蔽性需求切换"接触目标"的程度，灵活适配从合规监控到授权红队的全光谱场景。
🖥️ 双接口：Web UI + CLI
Web UI 降低门槛（点选即用），CLI 适配自动化与脚本编排，同一引擎覆盖"人"和"流程"两类使用者。
🛠️ 内嵌主流安全工具
原生集成 Nmap、Nuclei、DNSTwist、testssl.sh、Wappalyzer、TruffleHog、WAFW00F 等作为"Tool 类模块"，无需在多个工具间切换。
📡 全目标类型覆盖
不仅限于域名/IP，还支持邮箱、用户名、电话、比特币/以太坊地址、哈希、ASN、网段等，是少数"以人为中心"也能"以资产为中心"的 OSINT 平台。

四、应用场景

场景说明
🔍 渗透测试前置侦察黑盒/灰盒评估前的资产发现、子域名枚举、技术栈识别，为后续漏洞挖掘铺路。
🛡️ 威胁情报（CTI）批量富化 IOC（IP/域名/哈希），关联恶意基础设施，绘制攻击者画像。
🗺️ 攻击面管理（ASM/EASM）持续发现并监控暴露资产、影子 IT、开放端口、子域名接管风险。
🚨 应急响应（IR）事件调查中快速富化指标，定位关联基础设施与受影响资产。
🐛 数据泄露检测检测暴露凭据、被脱库邮箱、敏感文件、错误配置的云存储桶（S3/Azure/GCS）。
👤 人员/背景调查对高管、威胁行为者等个体进行开源情报画像（社交账号、泄露记录等）。
🐛 漏洞赏金（Bug Bounty）快速发现可报告的暴露面与子域名接管机会。

项目官方还按行业给出用例，覆盖 医疗、金融服务、政府、零售 等领域的合规监控与第三方风险评估。

选型建议：SpiderFoot 胜在"广度+自动化"，适合需要快速从零拼出目标全貌的场景；Maltego 胜在"可视化关系挖掘"，适合需要向人展示和深挖关联的分析；Recon-ng 胜在"轻量可脚本化"，适合资源受限或深度定制流水线。三者常被组合使用——SpiderFoot 采集 → Maltego 可视化。

六、优势与不足

✅ 优势

  • 数据源覆盖业界领先（200+），一站式
  • 模块级联自动关联，省去手工串联
  • 开源免费，社区活跃，Kali 内置
  • 被动/主动/全量三模式灵活
  • Web UI 降低使用门槛
  • 十余年沉淀，稳定成熟

⚠️ 不足

  • 核心模块高度依赖第三方商业 API Key（Shodan/Censys/HIBP 等），无 Key 则能力大打折扣
  • 全量扫描耗时较长，可能触发限流
  • 可视化关系图谱弱于 Maltego
  • 主仓库以 4.0 为主要发布节点，版本迭代节奏偏慢
  • 主动扫描存在被目标感知/触发 WAF 的风险，需谨慎授权

评语：SpiderFoot 是 OSINT 领域的标杆级开源项目。它以 200+ 数据源的压倒性广度、模块级联的自动关联能力，以及十余年的稳定维护，稳居渗透测试与威胁情报工具链的"侦察首站"位置。短板在于对第三方商业 API 的高度依赖和相对薄弱的可视化。对于任何需要"从目标反推全貌"的安全从业者，它都是值得常备的基础设施级工具。
