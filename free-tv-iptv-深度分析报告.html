1项目概述

What & Why —— 一份"只收录真正免费、且能用"的电视频道清单

Free-TV/IPTV 是一个开源的 M3U 播放列表项目，目标极其聚焦：把全世界真正免费的电视频道整理成一份可直接被任意 IPTV 播放器消费的 .m3u8 文件。这里的"免费"被严格定义 —— 要么是地面波/卫星免费开锁广播（DVB-T / DVB-S / 模拟信号），要么是官方在互联网上免费提供的流（Pluto TV、Plex TV、Redbox Live TV、Roku TV、Samsung TV Plus、YouTube 直播频道等）。

  • 核心价值主张：把"找免费直播源"这件反复碰运气的事，收敛为一个稳定可订阅的 raw 链接 —— 把它贴进播放器即可，链接长期有效、社区持续维护。
  • 使用门槛极低：不需要注册、不需要客户端、不需要 API Key，一个 https://raw.githubusercontent.com/Free-TV/IPTV/master/playlist.m3u8 走天下。
  • 覆盖广度：收录来自全球 70+ 国家与地区的免费频道（README 以国旗序列直观呈现），从美、加、英到日、韩、印、中东、拉美均有覆盖。
  • 明确的合法性边界：项目哲学白纸黑字声明 —— 不收录付费频道、不收录仅靠商业订阅才能观看的内容；以"是否在该国被官方免费提供"作为唯一收录标准。
"This is an M3U playlist for free TV channels around the World — either free locally (over the air) or free on the Internet." —— 项目 README

2技术架构

Markdown 即数据库 · Python 即编译器 · m3u8 即产物

项目最值得称道的设计是它的数据架构：它没有用数据库、没有用 CMS，而是把 Markdown 表格当作"单一事实源"（Single Source of Truth），再用一个 Python 脚本把人类可读的表格"编译"成机器可消费的 m3u8。这让"维护播放列表"这件事变得像"编辑一份 Wiki"一样轻量。

层次说明
数据源层lists/ 目录下的若干 .md 文件，每个文件代表一个分组（通常按国家/地区或频道类型组织）；文件首行 <h1> 即分组标题。频道信息以 Markdown 表格行存储。
状态标记每条频道的 URL 列以标记驱动：[>] 表示有效流（会被编入播放列表），[x] 表示失效（移入 Invalid 分类）。这是"编译期"的过滤开关。
元数据标记对频道质量/属性打标：Ⓢ = 非 HD（标清），Ⓖ = GeoIP 地理封锁，Ⓨ = YouTube 直播源 —— 用户一眼可知链路特性。
构建层make_playlist.py 解析上述 .md，按规则聚合、过滤（只取 [>]），输出根目录的 playlist.m3u8。
分发层最终产物通过 GitHub raw 链接 …/master/playlist.m3u8 对外发布；用户播放器订阅该 URL 即可。另有 SourceForge 镜像。
贡献工作流贡献者只改 .md、不改 .m3u8；通过 PR 增删频道并附"该频道确实免费"的佐证，由维护者审核合并 —— 一条清晰的、以 PR 为单位的策展流水线。

典型 .md 行与生成结果的对应关系示意：

📺 播放器兼容性

标准 m3u8 产物兼容几乎所有主流播放器：VLC、IPTV Smarters、TiviMate、Kodi、PotPlayer，以及智能电视内置 IPTV 应用，跨平台无门槛。

3核心创新点 / 差异化价值

它不是"又一个更大的频道大列表"，而是反其道而行 —— 砍掉冗余

🎯

① 质量优于数量（核心理念）

明确主张"支持的频道越少越好"：所有频道都应能正常播放、尽量 HD、且每个频道只保留一条 URL（不要 +1 回看、不要备用流、不要地区变体）。这与多数竞品"无脑堆量"完全相反。

🆓

② 严格的"仅免费"边界

白名单式收录标准：只收官方免费提供的频道（地面波/卫星开锁广播等），付费订阅频道一律不收 —— 在灰色地带丛生的 IPTV 生态里，划出了一条清晰的合法性红线。

🌍

③ "面向所有人"的内容准则

排斥性内容策略：不收成人频道、不收特定宗教频道、不收特定政党频道、不收"由他国资助针对本国"的频道 —— 让列表对全年龄段、全立场用户都"安全可用"。

📝

④ Markdown 即数据库

用 .md 表格作为单一事实源，状态用 [>]/[x] 标记驱动编译。维护播放列表 = 编辑文档，贡献门槛与 review 成本都极低，且数据天然可读、可 diff、可审计。

🏷️

⑤ 内嵌的可观测元数据

用 Ⓢ/Ⓖ/Ⓨ 等符号标注画质、地理封锁、来源类型 —— 用户在订阅前即可预判链路质量，减少"贴进去才发现全是黑屏"的挫败感。

⚡

⑥ 零依赖、一行接入

终端产物是一个长期稳定的 raw URL，任何支持 m3u8 的设备贴入即用，无需安装、无需账号、无中间件。对非技术用户也极度友好。

5竞品 / 相关项目对比

同处"IPTV 清单生态"，但策展哲学截然不同

项目 核心理念 频道规模 对本项目
Free-TV / IPTV 质量优于数量 · 每台仅 1 流 · 仅主流 · 仅免费 精选数百 本仓
iptv-org / iptv 尽可能全面收录全球公开频道，按国家/类别细分 数千～万级 对照更大更全，但失效率更高、噪音更多；本仓即以上游 streams 为采集源之一
iptv-org / epg 为海量频道生成 XMLTV 电子节目指南 — 互补本仓不含 EPG，可搭配它补节目单
Romaxa55 / world_ip_tv GitHub Actions 每日自动验活，主打"24/7 能播" 中等 对照重"自动验活"，本仓重"人工策展"
nasimali / epg-auto 每 24 小时自动合并生成 XMLTV EPG — 互补为本仓频道补 EPG 的可选工具
付费/灰色 IPTV 服务 转播付费/加密频道，常处于法律灰色地带 大 对立本仓明确拒绝此类内容，主打合规

结论：在 IPTV 清单生态里，iptv-org 走的是"大而全"，Free-TV/IPTV 走的是"小而精"。两者并非替代关系，而是不同取舍：要广度用前者，要"贴进去大概率能播、且合法干净"用后者。本仓还常被作为上游信号源，被其他工具二次加工。
