📖 项目简介与核心功能

Chrome DevTools MCP 是 Google ChromeDevTools 团队发布的官方 MCP (Model Context Protocol) 服务器，它让 AI 编码助手（Claude Code、Cursor、Gemini CLI、Copilot 等）能够直接操控 Chrome 浏览器进行自动化测试、调试、性能分析和网络检查。在 Google I/O 2026 上正式亮相，是目前最全面的浏览器-AI 桥接方案。

核心理念：AI 编码助手不应只能读写代码——它们还应该能看到、操作、调试运行中的 Web 应用。Chrome DevTools MCP 将完整的浏览器开发工具能力暴露给 AI，实现从"编码"到"验证"的闭环。

  • 44+ 专业工具 — 覆盖输入自动化、导航、性能分析、网络检查、调试、内存分析等 9 大类别
  • 连接活跃浏览器 — 可连接正在使用的 Chrome 实例（Chrome 144+ 自动发现），无需启动新浏览器
  • Performance Profiling — 录制性能 Trace，分析 CrUX 真实用户字段数据
  • 网络分析 — 拦截和检查 HTTP 请求/响应，分析加载瀑布流
  • 控制台智能分析 — 带源码映射的堆栈追踪，AI 可精确定位错误位置
  • 内存分析 — 堆快照、内存泄漏检测、对象分配追踪
  • Lighthouse 审计 — 一键运行性能、可访问性、SEO 等全面审计
  • Slim 模式 — 3 个精选工具覆盖日常任务，减少 ~78% Token 消耗

🏗️ 技术架构与特点

  • MCP 协议 — 基于 Anthropic 发起的 Model Context Protocol，通过 stdio 传输与 AI 客户端通信
  • Puppeteer 底层 — 使用 Puppeteer 库驱动浏览器自动化，成熟稳定的自动化引擎
  • Chrome DevTools Protocol (CDP) — 直接与 Chrome 的底层调试协议交互，获取最精确的性能和调试数据
  • 自动发现机制 — Chrome 144+ 内置 autoConnect，AI 客户端自动发现并连接活跃浏览器实例
  • 源码映射支持 — 错误堆栈自动映射回源代码行号，AI 可精确定位构建后代码中的 Bug
  • Slim 模式 — 仅暴露 3 个核心工具（导航、点击、截图），日常任务减少 ~78% Token 消耗
  • Headless 模式 — 支持 CI/CD 环境下的无头浏览器运行
  • WebMCP 实验性 — Chrome 149+ 原生支持网页通过 MCP 暴露工具给 AI，是 Web 平台的未来方向

🚀 快速上手指南

1

安装并启动

一行命令启动 MCP 服务器：npx chrome-devtools-mcp@latest

2

配置 AI 客户端

在你的 MCP 客户端配置文件中添加（以 Claude Code 为例）：

{ "mcpServers": { "chrome-devtools": { "command": "npx", "args": ["chrome-devtools-mcp@latest"] } } }
3

连接浏览器

Chrome 144+ 自动发现连接。旧版本需启动 Chrome 时添加 --remote-debugging-port=9222

4

开始使用

对 AI 说："打开我的开发服务器，点击登录按钮，截图看看页面效果"

5

进阶：Slim 模式

日常任务使用 npx chrome-devtools-mcp@latest --slim，仅启用 3 个核心工具，减少 78% Token 消耗

🏆 总结

Chrome DevTools MCP 是 2026 年 AI 开发工具链中最具里程碑意义的项目之一。它不仅是一个 MCP 服务器，更是 Google 对"AI 应该如何与浏览器交互"这一问题的官方回答。44+ 专业工具覆盖从基础自动化到深度性能分析的完整链路，Chrome 144+ 自动发现机制让集成几乎零成本，Slim 模式解决了 AI 工具的 Token 经济学难题。与 Playwright MCP 的"跨浏览器自动化"定位不同，Chrome DevTools MCP 走的是"调试优先、深度集成"路线——它关心的不是"让 AI 像人一样操作浏览器"，而是"让 AI 像资深前端工程师一样调试浏览器"。39K Stars 和 Google I/O 2026 的亮相已经证明：这是 AI 辅助 Web 开发的必备基础设施。
