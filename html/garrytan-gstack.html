🎯 项目简介

gstack 是 Y Combinator 总裁兼 CEO Garry Tan 开源的个人 Claude Code 工作流配置。它将单一的 Claude Code 助手转变为一个完整的虚拟工程团队 — 包含 CEO、设计师、工程经理、发布工程师、文档工程师和 QA 等多个专家角色。

Garry Tan 在过去 60 天内，以兼职方式（同时全职运营 YC），交付了 3 个生产级服务和 40+ 功能。他的 2026 年代码产出率比 2013 年提高了约 810 倍（按逻辑代码变更计算）。这套工具就是他实现这一生产力的核心方法。

核心理念： "一个人 + 正确的工具 = 比传统 20 人团队更快"。gstack 不是 Copilot，而是一支团队。

核心功能

  • /office-hours — YC 风格的办公室时间，6 个追问帮你重新定义产品
  • /plan-ceo-review — CEO 视角审视功能范围，4 种模式：扩展/选择性扩展/保持/缩减
  • /plan-eng-review — 工程经理锁定架构、数据流、边界情况
  • /review — 高级工程师 Code Review，自动修复明显问题
  • /ship — 发布工程师：同步 main、运行测试、审计覆盖率、推送 PR
  • /qa — QA 负责人：真实浏览器测试、发现 Bug、自动修复并生成回归测试
  • /design-shotgun — 设计探索器：生成 4-6 个 AI 设计变体，可视化对比选择
  • /design-html — 设计工程师：将设计稿转为可交付的生产级 HTML
  • /cso — 首席安全官：OWASP Top 10 + STRIDE 威胁模型审计
  • /codex — 跨模型第二意见，调用 OpenAI Codex CLI 独立审查
  • /browse — 真实浏览器控制，赋予 AI "眼睛"
  • /learn — 跨会话记忆管理，让系统随使用越来越聪明

🔄 Sprint 工作流

gstack 不是工具集合，而是一套完整流程。每个技能按 Sprint 顺序执行，前一步的输出自动成为后一步的输入：

💭 Think → 📋 Plan → 🔨 Build → 🔍 Review → 🧪 Test → 🚀 Ship → 📝 Reflect
# 一个完整的示例流程 /office-hours # → 生成设计文档 /plan-ceo-review # → CEO 审视范围 /plan-eng-review # → 锁定架构 # ... Claude 自动编写代码 ... /review # → Code Review + 自动修复 /qa https://staging... # → 真实浏览器 QA /ship # → 测试 + 覆盖率 + PR

架构亮点

  • 角色化 Agent 架构 — 每个 Slash Command 对应一个专家角色，有明确的方法论和输出格式
  • 链式工作流 — /office-hours 写设计文档 → /plan-ceo-review 读取 → /plan-eng-review 深化，技能间自动传递上下文

  • 跨 Agent 兼容 — 支持 Claude Code、OpenAI Codex CLI、Cursor、Factory Droid、Kiro、Hermes 等 10 个 AI 编码工具
  • GBrain 持久知识库 — 支持 PGLite 本地 / Supabase 云端，跨会话记忆积累
  • 跨模型审查 — /codex 调用 OpenAI Codex 独立审查，与 Claude 的 /review 交叉验证
  • Conductor 并行调度 — 支持 10-15 个并行 Sprint 同时运行
  • 多层安全防御 — 22MB ML 分类器 + Haiku 转录检查 + 随机 Canaries + DeBERTa 集成
  • Continuous Checkpoint — 自动 WIP 提交，崩溃恢复，ship 时自动清理
设计哲学： 所有技能都是纯 Markdown + Slash Command，零代码，MIT 开源。30 秒安装，Fork 即可定制。

📝 分析总结

gstack 代表了 AI 编码工具演进的下一个阶段 — 从单点辅助到完整工程流程自动化。它不是让你写代码更快，而是让你不再需要写代码，而是专注于产品决策和创意。

核心价值在于 Sprint 流程（Think → Plan → Build → Review → Test → Ship → Reflect）而非单个工具。每个技能自动衔接，形成完整的生产线。真正强大的地方是 10-15 个并行 Sprint — 一个人管理多个项目，像 CEO 管理团队一样。

争议点：810× 的生产力提升数字引发了关于 AI 代码质量 vs 人工代码质量的讨论。但 Garry Tan 强调的是"逻辑代码变更"而非原始 LOC，并公开了完整方法论和复现脚本。
