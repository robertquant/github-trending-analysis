🧭 项目概述

Continue 是 AI 编码助手赛道里最具影响力的开源项目之一。它把"AI 编码 Agent"做成了三种产品形态：一个命令行工具（CLI）、一个 VS Code 扩展、以及一个 JetBrains 插件，让开发者可以在自己习惯的 IDE 里直接用上 AI。核心理念可以一句话概括：

"我们的使命始终是确保开发者被放大（amplified）而非被自动化（automated），我们将继续秉持这一承诺。" —— Continue 官方

与 Cursor、Copilot 这类闭源、绑定单一厂商的产品不同，Continue 的三大差异化是：① 开源透明（Apache 2.0）；② 模型自由（任意云厂商或本地 Ollama 模型）；③ 多 IDE 深度集成（尤其是对 JetBrains 生态的支持，在开源竞品中相当稀缺）。开发者可以"自带模型"（Bring Your Own Model），把 OpenAI、Claude、Mistral 或本地开源模型接到同一个界面里。

2025 年，Continue 被 Cursor 收购，成为该赛道最受关注的事件之一。团队官方表态将继续坚持"开发者优先、开源"的承诺，但项目重心与路线图正处在过渡期。对关注开源、隐私与自主可控的团队而言，它仍是一个值得理解的重要参照系。

🏗️ 技术架构

1) 总体范式：声明式配置 + 模型无关 + IDE 原生

Continue 的架构以"把模型与功能解耦"为核心设计哲学。它不绑定任何特定模型或厂商，而是通过一套声明式配置（config.yaml）把"模型来源（providers）"与"功能角色（roles）"分离开来：

  • IDE 集成层：以扩展形式深度嵌入 VS Code / JetBrains，而非外部独立运行；聊天、Agent、自动补全都在 IDE 内完成
  • 配置层：config.yaml 统一声明模型、上下文提供者、规则、提示词等；放在全局 .continue 目录，可版本化、可团队共享
  • Provider 抽象：统一适配 OpenAI、Anthropic、Google、Ollama（本地）、OpenRouter 等多种模型来源
  • 角色（Roles）机制：同一个模型可被赋予一个或多个"角色"，不同角色可分别用不同模型
  • 上下文 / 工具层：通过 @codebase、@docs 等上下文提供者注入代码库与文档；原生支持 MCP（Model Context Protocol）
# config.yaml 示例 —— 用角色（roles）把模型与功能解耦
models:
  - name: "Claude Sonnet"
    provider: "anthropic"
    model: "claude-sonnet-4-6"
    roles: [chat, edit, apply]   # 用于对话 / 编辑 / 应用差异

  - name: "Qwen Coder (本地)"
    provider: "ollama"
    model: "qwen2.5-coder:1.5b"
    roles: [autocomplete]        # 轻量本地模型做 Tab 补全，零延迟、零成本

  - name: "Embeddings"
    provider: "ollama"
    model: "nomic-embed-text"
    roles: [embed]                # 为 @codebase 语义检索生成向量

2) 七大模型角色（Roles）—— 架构的灵魂

这是 Continue 最具辨识度的架构设计：把"AI 编码"拆成多个细分功能，每个功能可独立指定最合适的模型：

角色作用
chat对话式问答、代码讲解、澄清疑惑
autocompleteTab 自动补全（通常配轻量/本地模型，追求低延迟）
edit内联代码编辑（inline edit）
apply把模型生成的代码差异应用到文件
embed把文本转为向量，供 @codebase 语义检索使用
rerank对检索结果重排序，提升上下文相关性
summarize对话/上下文摘要，压缩长上下文

这种"功能—模型解耦"意味着：你可以用最强的 Claude/GPT 做 Agent 推理，用本地小模型做即时补全，用专用 embedding 模型做检索——各司其职、各取所长、成本可控。

3) 上下文提供者（Context Providers）与 MCP

Continue 通过上下文提供者把外部信息精准注入模型，构建出基于 RAG（检索增强）的代码理解能力：

  • @codebase：对整个代码库建立索引，基于 embedding 做语义检索，让 AI 跨文件理解项目结构与依赖关系
  • @docs：索引官方文档，让 AI 在写代码时能"查文档"，减少幻觉与过时 API 误用
  • MCP（Model Context Protocol）原生支持：接入 Anthropic 主导的开放协议，连接任意 MCP 服务器——数据库、API、文件系统、自定义工具皆可作为上下文与工具来源
  • 其他上下文：当前文件、选中代码、终端输出、Git diff、URL 等均可作为上下文提供者

💡 核心创新点

① 模型无关 + 本地优先：真正的"自带模型"

Continue 把"模型选择权"还给开发者。你可以接入任意云厂商，也可以完全用 Ollama 跑本地模型——代码与数据寸步不出本机。对隐私敏感、受监管或离线场景的团队（金融、医疗、政企），这是闭源工具结构性无法提供的能力。

② 七大角色机制：把 AI 编码拆解为可组合的能力

chat / autocomplete / edit / apply / embed / rerank / summarize 的角色抽象，让"用什么模型做哪件事"完全解耦。可用顶级模型做推理、本地小模型做补全、专用模型做检索，在效果与成本/延迟间精确权衡——这种灵活性在同类工具中独树一帜。

③ 三端覆盖，尤其填补 JetBrains 生态空白

同时提供 CLI、VS Code、JetBrains 三种形态。其中对 JetBrains（IntelliJ/PyCharm/WebStorm 等）的原生支持，在开源 AI 编码助手里相当稀缺——大量 Java/Kotlin/企业级后端开发者因此获益，而非被迫迁移到 VS Code 系。

④ 声明式 config.yaml：可版本化、可团队共享的配置

所有 Agent 行为通过 config.yaml 声明，可纳入 Git 团队共享——意味着团队的 AI 编码规范、提示词、模型选型可以像代码一样 review 与统一，而不是每个人各自配置。

⑤ 原生拥抱 MCP 开放协议

作为较早集成 Model Context Protocol 的编码 Agent，Continue 能接入庞大的 MCP 工具与数据源生态，把"代码库"以外的世界（数据库、API、知识库）安全地接入模型上下文。

⑥ Apache 2.0 + 零成本可用

Apache 2.0 协议商用友好；配合 OpenRouter 免费额度或本地模型，无需任何订阅即可体验完整 AI 编码能力，极大降低了上手门槛。

📋 总评

Continue 是开源 AI 编码 Agent 赛道里最系统化的标杆项目。它以 Apache 2.0 协议、模型无关设计、CLI/VS Code/JetBrains 三端覆盖、七大角色化配置、MCP 生态与本地优先隐私，构建出一条区别于 Cursor/Copilot 闭源路线的开放路径。其对 JetBrains 生态的原生支持与模型角色解耦在同类开源工具中独树一帜。

然而，2025 年被最大竞品 Cursor 收购是改变格局的事件。技术架构依然优秀（架构设计 9.2、开放性 9.0），但"未来确定性"被显著折价至 5.5——开源承诺能否延续、项目是否会被边缘化或转向，都存在真实的不确定性。

主要权衡：① 收购后的治理与协议走向待观察，自主可控诉求需谨慎评估；② 社区反馈在复杂重构类任务上稳定性偶有不足（被形容为"偶尔切不动的瑞士军刀"）；③ Agent 自主性与可视化审批流相比 Cline 略保守。

结论：仍是理解"开源 AI 编码"绕不开的参照系，技术架构与多端覆盖值得借鉴；但若以长期自主可控为硬性要求，建议同时跟踪 Cline / Aider / OpenCode 等独立开源方案，谨慎评估收购后的实际走向。
