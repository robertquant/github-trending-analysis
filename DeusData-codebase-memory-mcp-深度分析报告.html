项目概述

codebase-memory-mcp 是一个基于 MCP（Model Context Protocol，模型上下文协议）的代码智能后端服务器。它的核心理念是：与其让大模型在每次提问时一遍遍地读取文件（grep + read 循环），不如事先把整个代码库解析成一张持久化的知识图谱——节点是函数、类、路由、模块，边是调用、导入、继承、数据流等关系。模型只需发起一次图谱查询，就能拿到结构化的答案。

项目由 DeusData 团队开发，2026 年 2 月创建，仅约 4 个月就累积超过 5100 Star，最新版本 v0.8.1（2026-06-12）。它以纯 C 语言实现，编译为单个静态链接二进制，macOS / Linux / Windows 全平台覆盖，无需 Docker、无需运行时、无需 API Key——下载、运行 install、重启 Agent 即可使用。

一句话定位： 给 AI 编程助手装上一颗"代码记忆大脑"。它不是 LLM，而是把代码库变成可被亚秒级结构化查询的知识图谱，让任何 MCP 兼容 Agent（Claude Code、Codex、Gemini CLI 等 11 种）共享同一份代码理解。

技术架构

🔧 分层架构

项目采用"后端不内置 LLM"的清晰分层：codebase-memory-mcp 只负责构建与查询知识图谱，自然语言到图谱查询的翻译工作交给用户正在对话的那个 Agent（Claude Code 等）来完成。这样避免了额外 API Key、额外成本和额外模型配置。

用户："谁调用了 ProcessOrder？" ↓ Agent 调用 MCP 工具: trace_path(function_name="ProcessOrder", direction="inbound") ↓ codebase-memory-mcp: 执行图谱查询，返回结构化调用链 ↓ Agent: 用自然语言向用户解释调用链

🌳 解析层 · tree-sitter AST

  • 内置 158 种语言的 tree-sitter 语法（全部编译进二进制）
  • 通过 AST 分析提取函数、类、调用链等结构
  • 无需安装任何语言插件，永不"破损"

🔬 Hybrid LSP 语义类型解析

  • 为 Python/TS/JS/PHP/C#/Go/C++/Java/Kotlin/Rust 等 9 类语言提供轻量 C 实现
  • 兼容 tsserver、pyright、gopls、Roslyn、rust-analyzer 的类型解析算法
  • 支持参数绑定、返回类型推断、泛型替换、JSX 分发等

💾 存储层 · 内存优先 + SQLite

  • RAM-first 管线：LZ4 压缩读取、内存 SQLite、结尾单次落盘
  • 索引完成后内存即归还操作系统
  • 持久化至 ~/.cache/codebase-memory-mcp/

🔎 检索层 · 多信号融合

  • 语义向量检索：内置 Nomic nomic-embed-code（40K tokens, 768 维 int8）
  • BM25 全文检索：SQLite FTS5 + camelCase/snake_case 感知分词器
  • 11 路信号综合打分（TF-IDF、AST 轮廓、数据流、MinHash、图谱扩散等）

🔗 图谱层 · 丰富的边类型

  • CALLS / IMPORTS / DEFINES / IMPLEMENTS / INHERITS
  • HTTP_CALLS / ASYNC_CALLS（跨服务）
  • DATA_FLOWS、SIMILAR_TO（近克隆）、SEMANTICALLY_RELATED

🚀 分发层 · 单文件零依赖

  • 静态链接二进制，无共享库依赖
  • macOS 自动剥离隔离属性并 ad-hoc 签名
  • 支持 npm / PyPI / Homebrew / Scoop / Winget / AUR / go install

核心创新点

  • 纯 C 极致性能：在 AI 工具普遍用 Python / TypeScript / Rust 实现的时代，选择纯 C + 零依赖静态二进制，换来亚毫秒级查询和分钟级索引超大仓库的能力。这是其相对其它代码图谱工具最锋利的差异化武器。
  • 不内置 LLM 的"瘦后端"哲学：其它代码图谱工具往往内嵌一个 LLM 做自然语言→图谱查询的翻译，带来额外 Key、成本与配置负担。codebase-memory-mcp 借力 MCP 协议，让用户正在对话的 Agent 直接充当翻译层，架构更干净。
  • 团队共享图谱产物：把知识图谱压缩成单个 .codebase-memory/graph.db.zst 文件提交到仓库，队友 clone 后首次运行即可解压导入、只做增量索引，跳过全量重建。配合 merge=ours 的 .gitattributes 规则，二进制产物无合并冲突。
  • 无 API Key 的语义检索：把 Nomic 代码嵌入模型（40K tokens、768 维 int8 量化）直接编译进二进制，无需 Ollama、Docker 或外部 API，完全本地化运行，代码绝不离开本机。
  • 跨服务与跨仓库智能：自动识别 HTTP / gRPC / GraphQL / tRPC 路由并匹配调用点（含置信度评分）；通过 CROSS_* 边把多个仓库连成一张图，并提供"多星系"3D 可视化布局。
  • 基础设施即代码（IaC）索引：把 Dockerfile、Kubernetes 清单、Kustomize overlay 也作为图谱节点索引，与业务代码交叉引用——这在同类工具中极为罕见。
  • 一键适配 11 种 Agent：install 命令自动探测 Claude Code、Codex CLI、Gemini CLI、Zed、Aider、VS Code、Kiro 等并配置 MCP 入口、指令文件与钩子（且钩子设计为结构性非阻塞，绝不破坏 read-before-edit 不变量）。

应用场景

🐘 大型遗留代码库理解

  • 新接手百万行级项目时，用图谱快速搞清调用链、入口点与热点模块，而非逐个 grep。

🔧 AI Agent 辅助重构

  • 通过 detect_changes 把 git diff 映射到受影响符号并给出风险分级，做精准的变更影响分析。

🧹 死代码清理

  • 一键找出零调用方的函数（自动排除入口点），辅助技术债治理。

🌐 微服务架构梳理

  • 跨服务 HTTP/gRPC 调用匹配 + 跨仓库 CROSS_* 边，理清分布式系统全貌。

🔍 语义化代码搜索

  • "在哪里处理用户认证失败"这类意图查询，靠向量 + 11 路信号融合直接定位。

📚 架构决策留痕

  • manage_adr 跨会话持久化架构决策记录（ADR），团队知识不流失。
