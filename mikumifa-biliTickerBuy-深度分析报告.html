1项目概述

biliTickerBuy 是由开发者 mikumifa 创建的一款面向 Bilibili（B 站）会员购平台的开源购票辅助工具。 它通过直接调用 B 站会员购的公开/内部接口，在门票开售瞬间自动完成「登录态校验 → 项目识别 → 票种选择 → 创建订单 → 提交下单」的全流程， 以毫秒级的响应速度帮助用户抢到热门漫展（如 BiliBili World / BW、CP 同人展）、演唱会、演出、赛事等活动门票。

项目核心理念是「开源免费、简单易用、图形界面、速度极快」。不同于许多需要命令行操作、配置复杂的抢票脚本， biliTickerBuy 提供了基于 PySide6 的可视化图形界面（GUI），用户提前配置好收货地址、购买人实名信息与目标票种后， 只需一键启动，程序便会在指定开售时刻自动发起高频下单请求。Windows 用户甚至可以直接下载 release 的可执行文件，免安装开箱即用。

需要特别强调的是，该项目以「非侵入式」为设计原则，明确声明已控制请求频率、避免对 B 站服务器造成明显负载， 并通过 MIT License 严格限定「仅供个人学习与研究使用」，严禁用于商业代抢、牟利或任何违法/违反平台规则的用途。 这种克制的设计取向，也是它能在 GitHub 长期存活并获得社区认可的重要原因。

3技术架构

项目采用 Python 单体应用 + GUI 表现层 + 接口调用核心 的经典三层结构，核心抢票逻辑与界面解耦，便于维护与扩展。

① 表现层 · GUI

基于 PySide6（Qt for Python）构建可视化界面，支持票种配置、购买人/地址预填、开售时间设置、抢票启动与状态实时回显，降低普通用户使用门槛。

② 核心逻辑层

抢票主流程集中于 app_cmd/ 目录，buy.py 为下单核心：定时触发 → 轮询/直接下单 → 失败快速重试 → 订单创建与锁定。

③ 接口调用层

直接对接 B 站会员购接口，提前注入登录态（Cookie / 凭证）与必要的请求签名参数，省去浏览器渲染开销，实现纯接口级毫秒响应。

关键技术与设计要点

  • 纯接口调用，绕过浏览器：不依赖 Selenium/Playwright 等浏览器自动化，直接构造 HTTP 请求，省去页面加载、渲染、JS 执行的时间，把延迟压到最低。
  • 登录态预注入：用户提前完成扫码登录并保存 Cookie/凭证，开售瞬间无需再次鉴权，直接进入下单环节。
  • 信息预填与预热：购买人实名信息、收货地址、票种 SKU 在开售前全部就绪，避免开售时再交互填表。
  • 精准定时与快速重试：基于系统时间精准等待开售点，订单创建失败时采用受控的快速重试策略（频率受限，非侵入式）。
  • 验证码预演：针对会员购下单可能触发的验证码，提供「验证码预演练习」功能，提前演练以降低实战延误（见社区演示视频）。
  • 核心/界面解耦：抢票核心位于 app_cmd/，可独立于 GUI 以命令行方式运行，便于进阶用户与自动化场景调用。
🛡️ 非侵入式设计：项目在设计时严格遵循「非侵入式」原则，主动控制请求频率，避免对 Bilibili 服务器造成干扰，这也是它区别于灰产代抢工具、能够以开源形态长期存在的伦理与技术底线。
