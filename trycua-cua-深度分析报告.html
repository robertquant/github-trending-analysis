1项目概述

一句话定位：给每一个 AI 智能体配一台"云桌面"，让它像人一样看见屏幕、点击按钮、完成任务。

Cua（仓库 trycua/cua）是一套为计算机使用智能体（CUA）量身打造的开源基础设施。 所谓 CUA，是指一类不依赖 API 或代码级集成，而是像人类一样通过视觉看屏幕、用点击/输入/滚动等原始动作操控完整桌面来完成任务的 AI 系统。 这被普遍视为通用人工智能（AGI）落地最具想象力、也最艰难的方向之一。Cua 要解决的，正是这条路径上最底层、最容易被低估的"基础设施缺失"问题。

项目由 Francesco Bonacci（GitHub: @trycua）创立。他在微软研究院期间曾与 Dillon DuPont 共同主导并合著了 Windows Agent Arena（WAA）——一个用于大规模评估多模态 OS 智能体的 Windows 基准环境 （论文 arXiv:2409.08264）。正是这段"造过 Windows 端基准与沙箱"的实战经验，让他敏锐地意识到：整个行业缺的不是更聪明的模型，而是 一套能让任何模型、任何 Agent 框架都能即插即用的"计算机操控基础设施"。2025 年他在旧金山创办 Cua AI，入选 Y Combinator X25 批次。

Cua 提供四块拼图：Cua Drivers（后台计算机操控层）、Cua Sandbox（跨平台沙箱 SDK）、 Cua-Bench（基准与强化学习环境）和 Lume（基于 Apple Virtualization.Framework 的 macOS/Linux 高性能虚拟机）。 它们组合起来，覆盖了"训练 → 评估 → 运行"智能体的完整链路。截至当前，仓库累计 17,800+ Stars，是 2025 年增长最猛的开源 AI 项目之一， 采用 MIT 许可证，社区目标被明确表达为"让 cua-driver 成为计算机使用的事实标准协议"。

2技术架构

四大支柱：Drivers（操控层）· Sandbox（沙箱层）· Bench（评测层）· Lume（虚拟化层），云/本地同构 API。

Cua 采用monorepo 单仓多包组织，以 Python 3.11+ 为主要语言（SDK、Agent、Bench、Driver）， Swift 用于 macOS 原生驱动与 Lume（直接调用 Apple 私有/公开 Virtualization.Framework），底层依赖 QEMU、 Kasm（无头浏览器/桌面，MIT）和可选的 OmniParser（微软 UI 解析模型，CC-BY-4.0）。 设计哲学是"同一套 API，无论 OS、无论运行时、无论云端还是本地"——这是其最关键的工程取舍。

其中 Cua Drivers 是最具差异化的部分：它实现后台（background）计算机操控——Agent 在执行点击、输入、校验等动作时 不会抢占鼠标光标或前台焦点，意味着你可以在一边正常办公的同时，让 Agent 在后台默默操作另一个桌面环境完成任务。 它同时提供 CLI 工具与 MCP（Model Context Protocol）服务器，因此能被 Claude Code、Cursor、Codex、OpenClaw 等任意支持 MCP 的客户端直接调用。 Lume 则借助 Apple Silicon 的 Virtualization.Framework，在 M 系列芯片上跑出接近原生的 macOS/Linux 虚拟机性能，是该方案区别于传统 QEMU 慢速虚拟化的关键。

3核心创新点

Cua 的价值在于：它把"让 AI 操控电脑"这件事，从实验室 Demo 变成了可即插即用的工程基础设施。

① 后台计算机操控（Background Computer-Use）

最具差异化的能力：Agent 点击/输入/校验不抢占鼠标光标与窗口焦点。你可以正常办公，Agent 在后台静默操作——彻底解决了传统 CUA"一操作就抢屏、人机无法并行"的痛点，是走向"AI 同事常驻后台干活"的关键一步。

② 跨平台统一 API

一套 Sandbox API 通吃 Linux 容器/VM、macOS、Windows、Android 与自定义镜像。开发者无需为每个 OS 重写操控逻辑，切换平台只改一行镜像声明，大幅降低 CUA 的工程门槛。

③ 云端与本地同构

同一套 API 既能跑在 cua.ai 云端桌面，也能用本地 QEMU/Lume 自建。云端开箱即用、可弹性扩展；本地零成本、数据不出域。云端付费、本地免费的双轨策略兼顾了便捷与可控。

④ MCP 协议一等公民

原生提供 MCP Server，Claude Code、Cursor、Codex、OpenClaw 等主流编程 Agent 可一行命令接入。踩中了 MCP 生态爆发的时间窗口，让 Cua 成为"给编程 Agent 配电脑"的首选方案。

⑤ 评测 → 训练闭环

Cua-Bench 不仅能在 OSWorld/ScreenSpot/Windows Arena 上评估 Agent，还能导出操作轨迹（trajectories）用于强化学习训练。把"评测"与"训练"打通，是构建自研 CUA 模型的完整数据飞轮。

⑥ Apple Silicon 原生虚拟化

Lume 直接调用 Apple Virtualization.Framework，在 M 系列芯片上实现接近原生的 macOS/Linux VM 性能——远超传统 QEMU 的龟速体验，让"在 Mac 上跑 macOS 沙箱给 Agent 用"真正可用。

⑦ 安全覆盖的沙箱隔离

所有 Agent 操作都封装在隔离沙箱中执行——崩溃可丢弃（ephemeral）、快照可恢复、与宿主系统物理隔离。天然适合执行"不可信代码/不可信任务"，安全性远胜直接在真实桌面操作。

⑧ 创始团队的"地基级"经验

作者在微软主导过 Windows Agent Arena——这是 Windows 端 CUA 评测的事实基准。这份"既造过沙箱、又造过基准"的稀缺经验，让 Cua 一开始就站在了正确的工程抽象层级上。

4应用场景

凡是"需要让 AI 真正动手操作软件"的场景，都是 Cua 的用武之地。

  • 给编程 Agent 配电脑：让 Claude Code / Cursor / Codex 不仅写代码，还能自主打开 IDE、装依赖、跑测试、调试 GUI——真正"全栈动手"。
  • 构建自主 CUA：基于 Cua Agent 框架快速搭建"像人一样操作任意软件"的智能体，客服、运维、办公自动化皆可。
  • 跨平台 QA 自动化：用统一的视觉操控做 macOS/Windows/Linux 端到端测试，无需为每平台维护脆弱的选择器脚本。
  • RPA / 办公流程自动化：替代传统 RPA 操作 ERP、报表、财务软件等无 API、只有 GUI 的"陈旧但关键"系统。
  • 训练与评估 CUA 模型：Cua-Bench 在 OSWorld/ScreenSpot 上跑基准，导出轨迹做 RL 训练，服务自研 Agent。
  • 移动端自动化（Android）：沙箱支持 Android，可做 App 测试、移动端任务自动化、多点触控手势操作。
  • 安全沙箱执行不可信任务：把不可信代码/任务丢进隔离沙箱运行，崩溃即弃、不留痕迹，安全研究/蜜罐场景适用。
  • 云端桌面即服务：通过 cua.ai 给每个 Agent 配一台按需的云桌面，无需自建虚拟化集群。

典型采用画像：核心用户是AI Agent 开发者、编程工具团队、AI 基础设施工程师与前沿模型研究者。 他们通常已在构建基于 LLM 的自动化产品，苦于"让模型真正操控软件"这一底层难题——要么自己造沙箱轮子（昂贵且易错），要么受限于单一闭源方案。 Cua 用一套开源、跨平台、云/本地同构的基础设施，精准切中了这个正在快速膨胀的市场缺口。同时，因作者深厚的微软背景与 YC 加持， 它在企业级 CUA 落地（如操作 SAP/内部旧系统）方向也具备独特说服力。
