📋一、项目概述

第一代智能体是直接用裸 LLM API 拼出来的，能做简单聊天机器人和脚本任务，再多就力不从心。Claude Code、Codex 打破了这层天花板——它们是真正的"自主智能体"：你只给一个目标，而非预设步骤，它就利用你提供的上下文和工具去自主完成。

Flue 把这种架构开放给所有人。它内置的 TypeScript 编排层（harness）让任意模型都拥有真正自主工作所需的上下文与环境：会话（sessions）、工具（tools）、技能（skills）、指令（instructions）、文件系统访问，以及一个可安全执行操作的沙箱（sandbox）。你可以本地通过 CLI 运行，也能部署到任意托管运行时。

💡 核心定位："Agent 界的 Astro / Next.js"

Flue 不是又一个 AI SDK，而是一个运行时无关的框架——就像 Astro/Next.js 之于 Web。一次编写、构建，随处部署（Node.js、Cloudflare Workers、GitHub Actions、GitLab CI/CD、Daytona、Render）。它"像 Claude Code，但是 100% 无头且可编程"——没有必须有人在场的假设、没有 TUI、没有 GUI，只有 TypeScript。大部分"逻辑"以 Markdown 形式存在：skills、context、AGENTS.md。

"If you know how to use Claude Code (or Codex, OpenCode, Pi...) — then you already know the basics of how to build agents with Flue."（会用 Claude Code，就会用 Flue 构建智能体）

🏗二、技术架构

Flue 的架构围绕三个核心原语展开：Agent（智能体） → Harness（编排层） → Session（会话）。一个 Agent 是 agents/<name>.ts 源文件；init(createAgent) 生成一个 Harness（配置好模型默认值、工具、沙箱、文件系统、会话的句柄）；harness.session() 打开一个会话。复用同一 URL <id> 即可延续同一智能体实例。

① 分层架构（六层）

  • 编排层（Harness Runtime）：@flue/runtime 提供 harness、sessions、tools、sandbox 的统一运行内核。
  • 沙箱层（Sandbox）：核心创新。默认为每个 Agent 提供虚拟沙箱（由 Vercel 的 just-bash 驱动，内置 grep/glob/read/shell），比跑完整容器更快更省更可扩展，适合高流量/高规模智能体；也可选用 local()（Node 宿主直连 shell）或远程容器沙箱（Daytona/E2B 等）。
  • 消息驱动层（Message-Driven Agents）：通过 HTTP 或 WebSocket 在 /agents/:name/:id 接收消息；应用侧可用 dispatch(...) 向会话异步投递输入。Cloudflare 上由 Durable Objects 持久化会话状态，跨请求存活。
  • 工作流层（Workflows）：结构化自动化，由代码引导智能体推理从明确输入到成品的完整流程；可通过 flue run 在 CI/CLI 触发，或通过 HTTP 端点部署。
  • 持久化层（Durable Execution）：可持久化执行——已接收的工作可在崩溃/重启后通过持久化恢复进展。
  • 可观测层（Observability）：通过 OpenTelemetry、Braintrust、Sentry 或自定义观察者导出遥测/追踪/错误。

② 关键代码范式

最简 Agent（无容器、无工具，只有提示词与类型化结果），默认虚拟沙箱：

// .flue/workflows/hello-world.ts
import { createAgent, type FlueContext } from '@flue/runtime';
import * as v from 'valibot';

const translator = createAgent(() => ({ model: 'anthropic/claude-sonnet-4-6' }));

export async function run({ init, payload }: FlueContext) {
  const harness = await init(translator);
  const session = await harness.session();
  const { data } = await session.prompt(`Translate: "${payload.text}"`, {
    result: v.object({ translation: v.string(), confidence: v.picklist(['low','med','high']) }),
  });
  return data;
}

③ 模型与生态适配

  • 模型无关（LLM-agnostic）：统一 provider/model 写法，支持 anthropic/claude-*、openai/gpt-*、openrouter/moonshotai/kimi-k2.6 等；configureProvider() 支持企业 API 网关/代理/自托管 OpenAI 兼容端点。
  • MCP 适配：connectMcpServer() 将远程 MCP server 的工具接入智能体，密钥放 env 而非提示词/文件系统；默认 streamable HTTP，SSE 需显式声明。
  • 技能（Skills）：工作区技能放在 <cwd>/.agents/skills/<name>/SKILL.md，运行时按名激活；也支持静态打包导入（构建期校验 SKILL.md，含密钥/私钥的文件会被构建拒绝）。

💡三、核心创新点

  1. 内置 Agent Harness（编排层而非 SDK）：把 Claude Code/Codex 那种"真正自主智能体"的内部机制（session、tool、skill、fs、sandbox）抽象成可编程框架，让任意模型直接具备自主执行能力。
  2. 虚拟沙箱（just-bash 默认）：默认为每个智能体提供虚拟沙箱，无需容器即可拥有 grep/glob/read/shell——比逐智能体跑完整容器更快、更便宜、更可扩展，适合高并发大规模智能体场景。
  3. 运行时无关 / 写一次到处部署：同一份 TS 代码可在 Node、Cloudflare、GH Actions、GitLab、Daytona、Render 运行，真正像 Web 框架那样"一次构建、随处部署"。
  4. Markdown 驱动的智能体逻辑：大部分"逻辑"以 skills、context、AGENTS.md 形式存在 Markdown 中——开发者写得少、改得快、复用强。
  5. 可持久化执行（Durable Execution）：已接收工作在失败与重启间保留进度，契合生产级长任务/异步工作流。
  6. 子智能体（Subagents）与任务委派：defineAgentProfile() 定义专家角色，session.task() 在隔离会话中跑一次性子智能体；LLM 自己也能在 prompt 期间用 task 工具并行委派。
  7. 连接器（Connectors）机制：第三方沙箱/服务以 markdown 安装指令形式提供，flue add daytona | claude 由你的 AI 编码 agent 写出适配器——生态扩展极轻量。
  8. 消息驱动 + 异步投递：HTTP/WebSocket 长连接 /agents/:name/:id + dispatch() 异步输入，天然契合多租户客服/协作类产品。

🎯四、应用场景

🎫 Issue/Bug 分诊（CI）
CI 内 issue 触发 triage agent：复现、定位根因、判断是否预期、尝试修复。用 local() 沙箱直连 gh/git/npm。
💻 完整编码智能体
Daytona 远程容器沙箱 + git/Node/浏览器/克隆仓库，构建类 Claude Code 的自主编码 agent。
🎧 多租户客服智能体
部署到 Cloudflare，用虚拟沙箱 + 内置检索工具搜知识库，会话跨年持久化可续聊。
🔌 MCP 工具智能体
连接远程 MCP server（如 GitHub MCP），把认证工具安全交给 agent，密钥留在 env。
📊 结构化工作流
代码编排多步推理，从明确输入到结构化产出，valibot schema 校验返回数据。
🤖 自主后台智能体
无头无 GUI，长任务自主执行 + 持久化恢复，契合无人值守的后台 worker。
🔗 多渠道事件接入
从 Slack、Teams、Discord、GitHub 等接收已验证事件（Channels）驱动 agent。
🔬 可观测生产智能体
OpenTelemetry/Sentry/Braintrust 追踪，上线即带完整 telemetry。
默认端口 3583（电话键盘上的 "FLUE"）——细节里藏着 Astro 团队的工程品味。

🎯 差异化护城河

Flue 不与 LangChain 争夺"可组合链/检索"赛道，而是开辟"把 Claude Code 这类生产级 Agent Harness 产品化为可编程框架"的细分市场。最大差异化是 ① 默认无容器虚拟沙箱（just-bash，成本/规模优势）、② 真正的运行时无关一次部署、③ Markdown/Skills 驱动的极简开发心智。被社区称为"Next.js of AI"与"LangChain 替代"。

⚖️六、优势 / 局限

✅ 优势

  • Astro 团队背书：Web 框架领域的成熟工程文化与品味（端口 3583 等细节）。
  • 默认虚拟沙箱：just-bash 无需容器，快、省、可大规模。
  • 真正的运行时无关：Node / Cloudflare / GH Actions / GitLab / Daytona / Render。
  • Agent Harness 一等公民：session/tool/skill/fs/sandbox 内置，开箱即自主。
  • Durable Execution + 多租户会话持久化（Durable Objects）。
  • Markdown 驱动：skills/AGENTS.md，逻辑低代码、易复用。
  • 模型无关 + MCP 原生 + 连接器生态。
  • Apache-2.0，可商用；完整可观测性（OTel/Sentry/Braintrust）。

⚠️ 局限

  • 实验阶段（Experimental）：API 可能变更，不建议直接上核心生产。
  • 生态尚幼：connectors、社区案例、教程数量远不及 LangChain。
  • 虚拟沙箱能力边界：复杂环境（浏览器/重运行时）仍需 Daytona 等容器。
  • 部署门槛：Cloudflare dev 需 wrangler 依赖；多平台配置存在心智成本。
  • MCP 第一版限制：不自动探测传输、不 spawn stdio server、不处理 OAuth 回调。
  • 类型较重：强 TS + valibot schema 对非 TS 团队有学习曲线。
  • 品牌/文档站：flueframework.com 文档尚在完善中。

🏆七、综合评分：8.7 / 10

Flue 是一个定位精准、设计成熟、极具潜力的实验期框架。它抓住了"把生产级 Agent Harness 产品化"这一真实痛点，凭借 Astro 团队的工程实力、默认无容器沙箱的成本优势、以及真正的运行时无关部署，在拥挤的智能体框架赛道切出了清晰差异化。社区已有"Next.js of AI""LangChain 替代"的呼声，Boshen、Karolis Stulgys 等开发者公开关注。
