📋 一、项目概述

SimpleX Chat 是一个免费、开源、跨平台的端到端加密即时通讯应用，被官方定义为"第一个没有任何用户标识符的通讯平台"。它最反常识的一点是：在整个网络协议层面，不存在任何形式的用户 ID——既没有手机号、用户名、邮箱，也没有 Signal/Session 那样的公钥或随机数字标识。这正是它区别于市面上所有同类产品的根本所在。

"Unlike any other existing messaging platform, SimpleX has no identifiers assigned to the users — not even random numbers."

它的底层是 SimpleXMQ（用 Haskell 编写的参考实现），实现了 SimpleX Messaging Protocol (SMP) —— 一个传输无关（transport-agnostic）的客户端-服务器协议，用于在公共网络上异步、分布式、安全地进行单向消息传输。文件传输、音视频通话、群组聊天则由配套的 XFTP（文件传输协议）和 STL/RTC（WebRTC 信令加密）等子协议支撑。

核心理念：用"成对队列标识"取代"用户标识"

传统通讯软件（哪怕端到端加密如 Signal）都依赖某种用户标识符来路由消息：服务器必须知道"A 给 B 发消息"。这导致元数据（metadata）暴露——谁在和谁、何时、多频繁地通讯，本身就是隐私。SimpleX 的解法是：每建立一段联系，就生成一对临时的、只服务于这一条消息队列的标识符（服务器下发的随机 RID/SID + 客户端公钥 RK/SK），它们成对存在、彼此隔离，且与任何"用户身份"无关联。

结果：服务器能看到"某条队列上有消息在流动"，却无法把这条队列与"哪个人"绑定，更无法把一个人的不同联系人关联起来。这就是 SimpleX 所说的 metadata resistance（元数据抗性）。

⚙️ 二、技术架构

SimpleX 采用客户端-服务器拓扑，但服务器（SMP 中继节点）被设计为冗余的、可抛弃的（disposable），只做最简单的消息暂存与转发，不存储任何用户身份或长期关系。整体可分为四层：

┌──────────────────────────────────────────────────────────┐ │ 客户端层（App / CLI） │ │ iOS · Android · Desktop(Windows/macOS/Linux) · Terminal │ │ 本地存储消息数据库，私钥从不离开设备 │ ├──────────────────────────────────────────────────────────┤ │ 加密层（双棘轮 + PQ） │ │ Double Ratchet（前向保密 + 后续保密 + 可否认性） │ │ v5.6 起叠加 ML-KEM 后量子密钥交换（抗量子） │ ├──────────────────────────────────────────────────────────┤ │ 协议层（SMP / XFTP / RTC） │ │ SMP 单向队列 7 命令 5 响应 · XFTP 文件分块传输 │ │ 每条联系 = 独立队列，ID 由服务器随机生成，与用户无关 │ ├──────────────────────────────────────────────────────────┤ │ 中继层（SimpleXMQ Servers） │ │ 冗余可弃节点 · 可自托管 · 可叠加 Tor · 不存用户身份 │ └──────────────────────────────────────────────────────────┘

1. SimpleX Messaging Protocol (SMP) —— 极简协议设计

SMP 的原始设计哲学是最小化：最初版本仅有 7 条命令和 5 种服务器响应，全部通过 TCP 传输。它把消息建模为单向队列——发送方往队列里写，接收方从队列里取，服务器只是个"带锁的暂存箱"。一次双向对话由两条独立的单向队列组成。这种设计带来三个直接好处：

  • 无中心身份：队列 ID 与人解耦，服务器无法画像
  • 可抛弃中继：节点被封锁/失效，只需换一个，不影响身份（因为根本没有身份）
  • 传输无关：可跑 TCP，也可叠加 Tor，协议本身不绑定传输层

2. 加密层 —— Double Ratchet + 抗量子

消息内容的端到端加密采用与 Signal、Cwtch 同源的 Double Ratchet（双棘轮）算法，提供：

安全属性含义
前向保密（Forward Secrecy）即使长期密钥日后泄露，过往消息仍无法解密
后继保密 / 破损恢复（Post-Compromise Security）密钥被攻破后，会话会自动"愈合"，后续消息重新安全
可否认性（Deniability / Repudiability）消息无法被密码学证明是某人发出的（对抗"截图定罪"），这点优于 Session

在 v5.6（2024 年 3 月）版本中，SimpleX 在双棘轮之上叠加了 后量子（post-quantum）密钥交换层，引入 ML-KEM（原 Kyber），使加密具备抗量子计算攻击的能力——这是它领先于 Signal 等主流方案的一个亮点。

双棘轮会话状态以加密容器形式存储在服务器上，支持多设备并发访问 —— 既能多端同步，又不让服务器看到明文状态。

3. 中继层 —— SimpleXMQ 与自托管

SMP 服务器（中继节点）用 Haskell 实现，官方提供预设节点（如 smp11、smp12 等），但任何人都可以自托管（官方有完整部署文档）。中继节点之间无协调、无状态关联，是真正"可替换、可抛弃"的基础设施。全平台支持经 Tor 接入中继，进一步隐藏 IP 与网络层元数据。

💡 三、核心创新点

① 网络层零用户标识（行业唯一）

这是 SimpleX 最硬核、最原创的设计。Signal 有电话号、Session 有公钥 Account ID、Matrix 有 user ID、Briar 有 Tor onion 地址——所有竞品在协议层都有某种持久身份。SimpleX 彻底取消"用户"概念，只保留"联系（connection = 一对队列）"。这意味着攻击者无法通过收编服务器来还原社交图谱，因为图谱碎片化地分散在互不关联的队列标识里。

② 冗余可弃中继拓扑（Redundant Disposable Relays）

不像 Signal 依赖单一中央服务器集群，也不像 Briar 强依赖 P2P/Tor（牺牲易用性），SimpleX 走中间路线：多个独立中继节点异步转发，节点可随时更换、可自托管。既保留了 P2P 的去中心化与抗审查性，又通过中继避免了"双方必须同时在线"的 P2P 痛点。

③ 率先引入抗量子加密（v5.6）

在主流 E2EE 通讯软件仍在使用经典椭圆曲线时，SimpleX 已把NIST 标准化的 ML-KEM 后量子算法嵌入密钥交换，防御"先收割后解密（harvest now, decrypt later）"的未来量子威胁。对记者、维权人士这类需要长期保密的群体意义重大。

④ 可否认性（Deniability）

双棘轮天然提供可否认性：一条消息无法被密码学证明出自某人之手。这在高压环境下能对抗"截图即定罪"——截图可以被伪造，密码学上无法自证。这是 SimpleX 相对 Session（设计上不完全可否认）的一个明确优势。

⑤ 极简协议 = 可审计、可验证

SMP 仅 7 命令 5 响应的极简设计，使协议易于形式化分析与第三方审计。项目已通过 Trail of Bits 等机构的独立安全审计，并在博客公开报告——这在加密通讯领域是重要的可信度信号。

⑥ 全平台 + Tor + 自托管的一体化

同一套架构覆盖 iOS/Android/Desktop/Terminal 全平台，全平台支持 Tor，并提供完整自托管文档。对重视主权与审查规避的组织而言，这是一个"开箱即用、且不依赖任何单一供应商"的完整方案。

⚖️ 六、优势与局限

✅ 核心优势

  • 协议层零标识，行业唯一：从根上消除社交图谱与元数据关联，隐私模型最彻底
  • 密码学前沿：双棘轮 + ML-KEM 抗量子密钥交换，领先多数竞品
  • 独立安全审计：经 Trail of Bits 等机构审计并公开报告，可信度高
  • 去中心化 + 自托管：冗余可弃中继，任何人可部署，无供应商锁定
  • 全平台 + Tor 一体化：iOS/Android/Desktop/CLI 全覆盖，全平台叠加 Tor
  • 极简可审计协议：SMP 7 命令 5 响应，便于形式化分析与实现正确性

⚠️ 潜在局限

  • 易用性门槛：无统一账号意味着换设备/找回需依赖备份，新用户建立联系比 Signal 繁琐
  • 生态规模较小：用户基数远不及 Signal/WhatsApp，网络效应弱
  • 中继依赖：消息非真正 P2P，仍需中继节点（虽可自托管/叠加 Tor）
  • 抗量子仍在演进：PQ 方案标准与实现持续迭代，需跟进更新
  • 客户端实现复杂度：Haskell 核心带来高正确性，但贡献门槛相对较高

🏆 七、综合评价

SimpleX Chat 是 2026 年隐私通讯领域最具原创性与密码学严谨性的项目之一。它没有走"再优化一个 Signal"的常规路线，而是从协议第一性原理出发，提出"通讯不需要用户身份"这一激进却自洽的范式，并用极简协议、双棘轮+抗量子加密、冗余可弃中继、完整自托管把它工程化落地。
