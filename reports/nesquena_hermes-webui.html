1. 项目概述

Hermes WebUI 是 Hermes Agent（由 Nous Research 开发的自主 AI 代理）的官方浏览器端交互界面。它提供与 CLI 完全一致的功能体验——你在终端里能做到的事情，在浏览器里同样可以做到。

Hermes Agent 本身是一个"会自我成长的 AI Agent"，拥有持久记忆、自主调度、多平台触达等核心能力，支持通过 Telegram、Discord、WhatsApp、Slack、Home Assistant 等多种渠道与用户交互。而 Hermes WebUI 则是这一生态体系中的 Web 端入口。

核心定位：Hermes WebUI 是 Hermes Agent 的「轻量级可观测性与控制客户端」——而非一个简单的聊天前端。它直接与 Agent 运行时 API 对接，提供完整的 Agent 管理能力。

架构设计理念

项目的架构目标是将 WebUI 打造为一个薄层可观测性/控制客户端（thin observability/control client），通过 Hermes Agent 运行时 API 作为执行边界，而非直接导入或实例化 AI Agent。这意味着：

  • WebUI 不直接执行 AI 逻辑，仅作为 Agent 的前端代理
  • 所有核心能力（终端访问、文件操作、Web 搜索、记忆管理、技能系统）由 Hermes Agent 运行时提供
  • 前后端完全分离，后端通过 FastAPI 提供 RESTful API
  • 前端 React 应用通过 TanStack Query 管理服务端状态

部署方式

最简部署仅需一个 Docker 容器，WebUI 在进程内运行 Agent：

  • 单容器模式：一个 WebUI 容器包含 Agent 运行时，开箱即用
  • 分离模式：WebUI 连接远程 Hermes Agent API 服务器

3. 核心创新点

3.1 完整的 CLI 功能对等

WebUI 不只是聊天的前端——它实现了 Hermes Agent CLI 的完整功能对等。用户可以在浏览器中管理 Agent 的所有能力，包括终端操作、文件系统访问、技能管理等。

3.2 极简部署体验

与许多需要复杂配置的 AI 前端不同，Hermes WebUI 追求极致的部署简洁性：git clone → cp .env → docker compose up，三步即可运行。没有额外的构建步骤，降低了用户的使用门槛。

3.3 多会话管理

支持同时管理多个 Agent 会话，用户可以在不同的工作任务之间快速切换，这在 Reddit 社区中被广泛好评——"The feature set is great. I like having many sessions I can switch between while working on multiple things."

3.4 薄客户端架构

架构创新：WebUI 被设计为 Agent 运行时的"薄客户端"，通过运行时 API 通信而非直接实例化 Agent。这种解耦设计使得 WebUI 可以独立于 Agent 进行迭代，同时保持完整的功能一致性。

3.5 手机端适配

项目定位明确支持"from the web or from your phone"，在移动端也有良好的交互体验，让用户可以随时随地与 Agent 交互。

4. 应用场景

个人 AI 助理

将 Hermes Agent 部署在个人服务器上，通过 WebUI 随时访问。Agent 拥有持久记忆，能记住你的项目、习惯和偏好，随着使用不断成长。

开发者工作台

通过 WebUI 管理代码项目、执行终端命令、搜索文档。多会话支持让开发者可以同时处理多个项目，无需在终端和浏览器之间频繁切换。

自托管 AI 服务

对于注重隐私的用户和组织，Hermes WebUI 提供了完全自托管的方案。数据不离开你的服务器，无需依赖第三方云服务。

多通道 Agent 管理

作为 Hermes Agent 多通道生态（CLI、Telegram、Discord、WhatsApp 等）的 Web 端统一管理入口，提供最丰富的可视化操作界面。
