📋 一、项目概述

什么是 system-prompts-and-models-of-ai-tools？

这是一个由开发者 x1xhlol 创建和维护的开源项目，被誉为「AI 历史上最大的提示词泄露事件」。该仓库系统性地收集了当今主流 AI 工具的完整系统提示词（System Prompts）和模型配置信息，涵盖了 28+ 款知名 AI 编码和生产力工具，总计超过 6,500 行系统提示词内容。

🏗️ 三、技术架构深度分析

3.1 系统提示词的通用架构模式

通过分析 28+ 款 AI 工具的系统提示词，可以发现它们共享一套相似的架构模式。这些提示词通常由以下核心模块组成：

  • 🎯

    角色定义层（Role Definition）

    定义 AI 的身份、能力和行为边界。例如 Cursor 将自己定义为「一个由 AI 驱动的代码编辑器」，Claude Code 则强调自己是「命令行工具」。每个工具都在角色定义中注入了品牌独特的措辞风格。

  • 🔧

    工具调用层（Tool Orchestration）

    定义 AI 可以调用的外部工具集合及其使用规范。Cursor 定义了代码编辑、文件搜索、终端执行等工具；Devin 则定义了浏览器操作、代码部署等更复杂的工具链。工具调用的精确描述直接决定了 AI 的能力边界。

  • 🛡️

    安全护栏层（Safety Guardrails）

    包含各种安全限制和边界条件处理。几乎所有工具都在系统提示词中加入了「不要执行危险操作」「不要删除重要文件」「请求用户确认」等安全约束。然而，这些约束如果暴露，攻击者可以精确定位并绕过。

  • 📝

    输出格式层（Output Formatting）

    规定 AI 输出的格式规范，包括代码风格、注释密度、Markdown 格式等。不同工具在这一层的设计差异巨大——Cursor 追求简洁实用的代码输出，而 Lovable 则注重生成完整的可运行项目。

  • 🧠

    推理策略层（Reasoning Strategy）

    指导 AI 如何分析问题、制定计划、选择最优方案。Claude Code 采用了「Think step by step」式的链式推理，Devin 使用了更复杂的「Plan → Execute → Verify」三阶段架构。

3.2 代表性工具的提示词设计特点

Cursor — 模块化设计

Cursor 的系统提示词采用了高度模块化的设计，将不同的功能（代码编辑、搜索、终端操作）封装为独立的工具描述。每个工具都有清晰的输入/输出规范和错误处理逻辑。这使其提示词虽然复杂，但可维护性极高。

Devin — 自主编航

Devin 的提示词揭示了一个完全自主的 AI 代理架构：它被赋予了浏览网页、操作浏览器、运行命令、编辑代码、部署应用的全套能力。其系统提示词更像一个「操作手册」，而非简单的行为约束。

Claude Code — 终端原生

Claude Code 的提示词体现了「终端优先」的设计理念。它直接与 shell 交互，使用结构化的工具调用来读写文件、执行命令。提示词中对 git 操作、文件系统导航和错误恢复有极为详细的指导。

Lovable — 全栈生成

Lovable 的提示词侧重于从自然语言描述生成完整的前端应用。它包含了丰富的 UI/UX 设计指南、组件库使用规范和响应式设计约束，旨在生成可以直接部署的 Web 应用。
