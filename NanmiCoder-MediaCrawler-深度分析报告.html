📌 一、项目概述

NanmiCoder/MediaCrawler 是一款功能强大的多平台自媒体数据采集（social media crawling）工具，由开发者 NanmiCoder 个人开源。它将目标锁定在长期让爬虫开发者头疼的"国内主流社交/内容平台"——支持小红书、抖音、快手、B站、微博、贴吧、知乎共 7 大平台的公开信息抓取，覆盖笔记、视频、帖子、评论等核心内容形态。

之所以爆红（GitHub 累计 43k+ Stars，曾连续数日霸榜 GitHub Trending），核心原因在于它精准切中了一个长期痛点：这些平台无一例外都部署了复杂的 JS 加密签名 + 反爬风控（如小红书的 x-s / sign、抖音的 a_bogus / X-Bogus 等）。传统做法需要逆向工程师逐个破解加密算法再用 Python 复现，门槛极高且算法一更新就失效。MediaCrawler 给出了一条更"工程化"的捷径。

项目默认使用 CDP 模式连接用户已有的 Chrome 浏览器，可以复用浏览器已有的登录状态、Cookie、扩展等，大幅降低平台风控检测风险。

项目以 Python 为开发语言，协议层面定位为技术研究与学习工具，官方文档站点为 nanmicoder.github.io/MediaCrawler。它面向的受众是：数据分析师、舆情/市场研究人员、社媒运营、爬虫技术学习者、需要构建社媒数据集的研究者。除了开源版，作者还维护一个功能更强（多账号、强化 IP 代理、去 Playwright 依赖、支持 Linux/Docker 部署）的 MediaCrawlerPro 重构版本，作为商业化/进阶形态并存。

🏗️ 二、技术架构

MediaCrawler 的架构设计围绕"用真实浏览器环境解掉加密这道题"这一核心哲学展开，整体分为采集层、平台适配层、数据存储层与基础设施层。

1. 核心技术哲学：Playwright + 免逆向 JS 执行

这是整个项目最关键的设计决策，也是它区别于传统爬虫框架的根本所在：

  • 不逆向，直接执行：项目并没有用 Python 完整复现各平台的加密算法，而是借助 Playwright 拉起一个真实（或带登录态的）浏览器环境，在该环境里直接调用平台原生的加密 JS，把所需的签名参数（sign、a_bogus 等）算出来再回传给 Python 发起 HTTP 请求。
  • 收益巨大：把"破解加密算法"这个高门槛、易失效的工作，降级为"在浏览器里调一个函数"——大幅降低逆向难度，且对平台加密逻辑的小幅变更具备一定鲁棒性。
  • 登录态可复用：浏览器保留登录成功的上下文（Cookie / 会话），可缓存复用，免去反复扫码登录。

3. 关键设计要点

  • 模块化 / 抽象基类设计：每个平台对应独立的 Crawler 模块，遵循统一的抽象接口（搜索 / 详情 / 评论等）。新增一个平台只需实现该接口，便于维护与扩展。
  • 登录态管理：支持扫码登录（QRCode）、手机号登录、Cookie 登录三种方式，登录态持久化缓存，避免重复登录触发风控。
  • CDP 模式：默认以 Chrome DevTools Protocol 连接用户已有的 Chrome 实例，复用其登录状态、Cookie、扩展，使请求行为更贴近真人，降低风控检测风险。
  • 反爬对抗：通过 Playwright 模拟真实浏览器行为 + IP 代理池轮换降低被封风险；Pro 版进一步强化多账号与代理。
  • 数据流向清晰：采集 → 解析 → 存储三段解耦，存储层可插拔。
