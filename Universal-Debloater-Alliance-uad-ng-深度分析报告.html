💻 主语言

Universal Android Debloater Next Generation（简称 UAD-ng） 是一款跨平台桌面 GUI 工具，通过 ADB（Android Debug Bridge）连接手机，帮助用户在无需 Root 的前提下，安全地卸载运营商与厂商预装的臃肿软件（bloatware）与隐蔽的系统应用。它的三大目标非常清晰：提升隐私、提升安全（收缩攻击面）、延长续航与性能。

值得注意的是，它并非从零起步，而是原版 UAD（作者 @0x192）的社区接力分支（detached fork）。在原作者逐渐放缓维护后，Universal-Debloater-Alliance 联盟接过了维护权，让这个被无数用户视为"神器"的项目焕发新生，持续更新包名数据库与设备适配。r/dumbphones 等社区直接称其为"圣杯（HOLY GRAIL）"。

它在隐私上极其克制：官方明确声明 UAD-ng 不收集也不上传任何用户数据，唯一的对外网络请求是两个指向 GitHub 的 GET——一个用于拉取最新的包名安全分级列表，一个用于检查版本更新。

2) 工作原理：免 Root 是如何做到的？

关键在于 ADB 的 多用户卸载（per-user uninstall）能力。Android 系统应用属于 system 分区，普通用户无法真正删除；但 ADB 拥有 shell 级权限，可以针对特定用户（通常是 --user 0，即机主）执行卸载/禁用：

# UAD-ng 实际等价命令（对当前用户卸载，不改 system 分区）
adb shell pm uninstall -k --user 0 <package_name>
# 优势：免 Root、可一键还原；代价：恢复出厂设置后应用会回来

UAD-ng 把这套流程图形化、批量化、安全化：连接 → 枚举设备已装包 → 用内置知识库给每个包打上"安全分级"与"类别"标签 → 用户勾选 → 批量执行，并记录操作日志便于回滚。

3) 安全分级机制（核心设计）

UAD-ng 维护的通用卸载列表是其真正的护城河——一套由社区多年沉淀、覆盖各 OEM（三星 / 小米 / OPPO / 索尼等）与运营商的包名知识库，把每个包分为若干推荐操作档位：

档位含义风险
Recommended（推荐）明确可安全移除的臃肿件：运营商应用、Google/OEM 重复应用、遥测类低
Advanced（进阶）可能有用、需判断的功能性应用，需一定了解中
Expert（专家）含关键系统组件，误删可能导致相机/电话/设置失效甚至变砖高
Uninstall / Restore所有操作均可一键还原，工具记录完整变更日志—

⚠️ 工程警示：UI 默认聚焦"Recommended"档；贸然进入 Expert 级并勾选可能导致设备功能缺失或 bootloop。社区里流传着多部"我清干净了安卓……然后学到惨痛一课"的视频与帖子。

💡 核心创新点

  1. 免 Root × 跨平台桌面 GUI 的稀缺定位：在"Root 党"（Magisk/KernelSU）与"手机端 Shizuku 党"（Canta）之外，UAD-ng 卡住了"PC + ADB、免 Root、Windows/macOS/Linux 通吃"这一独特生态位，门槛低、风险可控。
  2. 通用卸载列表（UAD List）—— 行业事实标准：它维护的包名安全分级库，已被 Canta、SD Maid SE（AppControl）、AppManager、android-debloat-list 等竞品直接消费。UAD-ng 既是工具，也是整个去臃肿生态的知识底座。
  3. 隐私优先，零遥测：GPL-3.0 + 仅两个 GitHub GET 请求 + 无账号无云端。在"清理类工具常被怀疑偷数据"的背景下，这一点对隐私社区（PrivacyGuides / Techlore / r/fossdroid）至关重要。
  4. Rust 重写带来工程现代化：相比许多同类（C# / Java / Electron），Rust 带来单文件分发、低内存占用、内存安全，并通过 Nix flake 实现可复现构建，工程水准在桌面小工具中属于上乘。
  5. 社区接力（Fork-to-Alliance）的可持续模式：原项目停滞后，由联盟接管并持续迭代至 v1.2.0（2026-01）、144 位贡献者、2015 次提交——证明开源项目"换手不换魂"的成功路径。
  6. 批量操作 + 多用户 + 一键还原：支持跨多用户（--user）批量卸载/禁用，并完整记录变更日志以便随时还原，把原本需要逐条手敲 ADB 的繁琐流程产品化。
