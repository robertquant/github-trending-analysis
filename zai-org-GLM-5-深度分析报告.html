🧭 项目概述

GLM-5 是智谱 AI（Z.ai）发布的最新一代旗舰基座大模型，承载着智谱从 "Vibe Coding（凭感觉写码）"升级到 "Agentic Engineering（智能体工程）" 的产品哲学。它不是又一个"通用聊天模型"，而是被明确定向训练（purpose-built）于两件事：复杂的系统工程与长周期（long-horizon）的 Agent 任务。

"Scaling is still one of the most important ways to improve the intelligence efficiency of AGI. ……GLM-5 delivers significant improvement compared to GLM-4.7 …… and achieves best-in-class performance among all open-source models in the world on reasoning, coding, and agentic tasks, closing the gap with frontier models." —— GLM-5 Technical Report

相较上一代 GLM-4.5（355B 总参 / 32B 激活），GLM-5 将规模一举放大到 744B 总参 / 40B 激活，预训练数据从 23T 增长到 28.5T tokens，并引入 DeepSeek Sparse Attention 显著压低了部署成本。在后训练阶段，团队自研了 slime 异步强化学习基础设施，让 RL 训练得以大规模、细粒度地迭代——这是 GLM-5 能在"胜任（competence）"之上迈向"卓越（excellence）"的关键。

在评测上，GLM-5 系列给出了非常硬核的成绩单：GLM-5.1 在 SWE-Bench Pro（真实工业级代码修复）上以 58.4% 暂列榜首，超越 GPT-5.4（57.7%）与 Claude Opus 4.6（57.3%）；在 NL2Repo（从需求生成完整仓库）上以 42.7% 领先 Claude 的 33.4%；GLM-5 在 Vending Bench 2（模拟经营一年的长程任务）上以 4432 美元余额排名开源第一，逼近 Claude Opus 4.5。一句话：这是目前开源阵营中少数能在 Agent 与编码维度正面挑战顶级闭源模型的产品。

🏗️ 技术架构

1) 预训练：更大规模 MoE + DeepSeek 稀疏注意力

GLM-5 延续并强化了智谱一贯的 MoE（Mixture-of-Experts，混合专家）路线。核心数字：

  • 总参数 744B，单 Token 激活约 40B（约 256 个专家中按需激活一小部分，激活率 ~5.9%）。这意味着它拥有"大模型的容量"，却以"中等模型的算力"运行——单位 Token 的推理 FLOPs 远低于同等总参的 dense 模型。
  • 预训练数据 28.5T tokens（较 GLM-4.5 的 23T 显著扩充），覆盖更广的代码、数学、多语料与长文本分布。
  • DeepSeek Sparse Attention (DSA)：动态稀疏注意力，约 90% 的注意力矩阵为稀疏，在长序列上把注意力计算量砍掉近一半。GLM-5.2 进一步在每 4 层稀疏注意力间复用同一个 indexer，再次降低单 Token FLOPs。

这套组合拳的直接收益是：在不牺牲长上下文能力的前提下，长序列场景部署成本下降约 50%——这是 GLM-5 把"超大模型"做成"可落地大模型"的核心工程突破。

2) 后训练：slime 异步 RL 基础设施

RL（强化学习）被认为是把预训练模型的"胜任"打磨成"卓越"的必经之路，但在 LLM 规模上高效跑 RL 长期是个工程难题。智谱为此自研并开源了 slime——一套异步强化学习基础设施：

  • 大幅提升训练吞吐与效率，使更细粒度、更多次迭代的后训练成为可能。
  • 支持长程 Agent 任务的 RL 优化——这是 GLM-5.1 能"跑得越久、效果越好"（数百轮、上千次工具调用持续优化）的底层支撑。
  • 把"模型在长任务里是否真能持续保持有效"作为训练信号，而非只看首轮表现。
"Previous models—including GLM-5—tend to exhaust their repertoire early …… Giving them more time doesn't help. GLM-5.1, by contrast, is built to stay effective on agentic tasks over much longer horizons. …… The longer it runs, the better the result." —— GLM-5.1 发布说明

3) 部署：多框架 + 国产芯片原生适配

GLM-5 系列从一开始就把"可落地、可自主可控"作为一等公民，提供完整的多框架、多芯片部署链路：

# vLLM（FP8，张量并行 8 卡，投机解码 MTP）
vllm serve zai-org/GLM-5.1-FP8 \
  --tensor-parallel-size 8 \
  --gpu-memory-utilization 0.85 \
  --speculative-config.method mtp \
  --speculative-config.num_speculative_tokens 3 \
  --tool-call-parser glm47 \
  --reasoning-parser glm45 \
  --enable-auto-tool-choice \
  --served-model-name glm-5.1-fp8

# SGLang（EAGLE 投机解码）
SGLANG_ENABLE_SPEC_V2=1 sglang serve \
  --model-path zai-org/GLM-5.1-FP8 \
  --tp-size 8 \
  --tool-call-parser glm47 \
  --reasoning-parser glm45 \
  --speculative-algorithm EAGLE \
  --speculative-num-steps 3 \
  --mem-fraction-static 0.85
  • 推理框架：vLLM（v0.19.0+）、SGLang（v0.5.10+）、xLLM、KTransformers 全部官方支持，并提供 Docker 镜像（如 vllm/vllm-openai:glm51）。
  • 国产芯片 Day-0 适配：通过 vLLM-Ascend、xLLM 原生运行于华为昇腾；借助 FlagOS 跨芯适配层，GLM-5.2 在发布当日即覆盖四款国产芯片（华为昇腾、摩尔线程、寒武纪等七大平台），是国产算力生态的旗舰模型。
  • 投机解码：原生支持 MTP / EAGLE，进一步提升推理吞吐。

4) 硬件门槛与"轻量化"方案

全精度 / FP8 是企业级配置，但社区已把门槛压到极低：

💡 核心创新点

① "跑得越久越好"的 Agent

GLM-5.1 打破了"模型用尽套路后就停滞"的固有瓶颈：通过反复回顾推理、修订策略，能在数百轮迭代、上千次工具调用中持续优化，把"长程有效性"作为模型能力的核心维度。

② MoE + DSA 的"大而省"

744B 容量 / 40B 激活的 MoE，叠加 ~90% 稀疏的动态注意力，在保留长上下文能力的同时把长序列部署成本砍掉约一半，让"旗舰级模型"真正具备落地经济性。

③ slime 异步 RL 基础设施

自研并开源的异步 RL 训练栈，大幅提升训练吞吐，支撑长程 Agent 任务的细粒度后训练——把"工程基础设施"也变成了可复用的开源资产。

④ 1M 可用上下文

GLM-5.2 在所有 Coding Plan 层级提供可用的百万级 Token 上下文，可承载"项目级"工程上下文，一次任务覆盖完整代码库。

⑤ 国产算力 Day-0 适配

原生兼容华为昇腾、摩尔线程、寒武纪等七大国产芯片平台，借助 FlagOS 实现"发布即覆盖"，是国内自主可控大模型的标杆。

⑥ 真实工业级编码 SOTA

在 SWE-Bench Pro、NL2Repo、Terminal-Bench 2.0 等真实世界（而非合成）编码基准上登顶开源、甚至超越顶级闭源模型。

🎯 应用场景

场景说明
🤖 自主编码 Agent作为 Claude Code / Cline / Continue 等编码 Agent 的后端模型，进行真实工程级代码生成、调试、重构与仓库级任务（NL2Repo）。
🛠️ 复杂系统工程前后端全栈开发、终端操作（Terminal-Bench）、长程跨文件改动；CC-Bench-V2 显示在前端、后端、长程任务上全面进步。
⏳ 长程自主任务数小时甚至更长时长的自主运行（GLM-5.1 支持最长约 8 小时自主任务）；如模拟经营一年的 Vending Bench、持续运维、长周期数据分析。
📐 深度推理 / 数学推理能力较 GLM-4.7 大幅提升，适合复杂数理推理、规划与多步决策。
📑 超长文档 / 代码库理解1M 上下文可一次性吃下大型代码库或海量文档，做整体理解、检索与重构。
🏢 私有化 / 合规部署金融、政务、央国企等对数据出域敏感的场景，借助国产芯片 + 自托管实现端到端自主可控。
🔌 工具调用 / 多智能体原生 tool-call（--tool-call-parser glm47）与 reasoning 输出，适合编排多 Agent 工作流。
