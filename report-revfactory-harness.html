项目概述

revfactory/harness 是一个为 Claude Code 设计的 Meta-Skill（元技能）插件，定位为「团队架构工厂」。它的核心理念极其简洁——用户只需用一句话描述自己的领域需求，Harness 就能自动生成完整的多智能体团队架构，包括专业化的 Agent 定义和它们所需的技能集。

💡 核心价值主张：将复杂的多 Agent 系统搭建工作，从手工编写、容易出错、难以保持一致性的繁琐过程，变成一行命令即可完成的自动化流程。根据作者的 A/B 测试，使用 Harness 后代码任务质量平均提升 60%（49.5 → 79.3 分）。

该项目位于 Claude Code 生态系统的 L3 Meta-Factory 层，具体属于 Team-Architecture Factory 子层——即「生成其他 Harness 的 Harness」。这不是一个普通的工具插件，而是一个架构级别的设计器。

六种架构模式

🔗

Pipeline（流水线）

顺序依赖任务，前一 Agent 的输出作为后一 Agent 的输入。适用于有明确工序的流程。

🔀

Fan-out/Fan-in（扇出/扇入）

并行处理独立任务，结果汇聚合并。适用于可并行化的批量分析场景。

🎯

Expert Pool（专家池）

根据上下文动态选择最合适的专家 Agent 执行。适用于需要按需调配的场景。

📝

Producer-Reviewer（生产-审查）

生成与质量审查分离，确保输出质量。适用于代码审查、文档校对等。

👁️

Supervisor（监督者）

中央 Agent 动态分配任务，统筹全局。适用于复杂项目管理。

🏗️

Hierarchical Delegation（层级委派）

自顶向下的递归委派，支持多层级分解。适用于大规模复杂系统。

🧠

L3 Meta-Factory 定位

不是直接提供技能，而是生成技能和团队的工厂。这是 Claude Code 生态中最高层次的抽象——Harness 生成其他 Harness。

生态位分析

Harness 的差异化优势在于其「架构设计」定位。市面上大多数 Agent 工具要么是运行时框架（LangGraph、CrewAI），要么是具体技能目录（wshobson/agents）。Harness 填补了一个独特的空白——如何系统性地设计多 Agent 团队的组织架构。这类似于软件开发中「架构师」与「程序员」的分工：Harness 做架构设计，其他工具做具体执行。
