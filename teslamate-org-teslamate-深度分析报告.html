1项目概述

一句话定位：把你的特斯拉变成一台可量化、可回溯、可自动化的"数据资产"。

TeslaMate 是一款面向特斯拉车主的自托管数据记录器（data logger）。它最初由 Adrian Kumpf（@adriankumpf）于 2019 年 创建，灵感来自更早期的 TeslaLogger 项目， 但从第一天起就以"现代软件工程范式"重新构建——选择 Elixir 语言、清晰的分层架构、PostgreSQL 持久化、 Grafana 可视化，并全面容器化。如今项目已迁移至 teslamate-org 组织，由社区共同维护。

它要解决的核心痛点是：特斯拉官方 App 与车机只给你"当下的状态"，却不给你历史——无法回顾每一次行程的能耗曲线、 无法追踪电池容量在数年间的衰减趋势、无法精确统计充电花了多少钱、更无法把"车辆到家的瞬间"接入智能家居做自动化。TeslaMate 把这些数据持续地、细粒度地沉淀到你自己掌控的数据库里，把"用车经验"升级为可分析的数据资产。

截至当前，TeslaMate 仓库累计 6,000+ Stars、750+ Forks，在 self-hosted 汽车类目中长期稳居第一。 项目采用 MIT 许可证，通过 Docker / Docker Compose 一键部署，支持 x86 与 ARM（树莓派、NAS、家庭服务器皆可）。 生态衍生出 TeslaMateApi（Go 编写的 REST 包装层）、TeslaMate ABRP（行程规划对接）等大量周边项目，是特斯拉数据自助化的事实标准。

2技术架构

核心机制：Elixir/OTP 调度器持续拉取 Tesla 云端数据，落库 Postgres，再以 Grafana + MQTT 多路输出。

TeslaMate 是一个典型的事件驱动 + 轮询混合架构。其采集层由 Elixir 的并发原语 （GenServer / Supervisor 树，运行于 Erlang BEAM 虚拟机）驱动，天然适合"一台车一个轻量进程"、 "可弹性扩展多车"、"崩溃自动重启"这类长期常驻、高容错的采集任务。Web 管理界面基于 Phoenix 框架 （大量采用 LiveView 实现实时、无重载的交互体验）。

采集层面 TeslaMate 同时使用两条通道：Tesla REST API 按"车辆睡眠友好"的间隔轮询电量、位置、里程等状态 （会在车辆休眠时主动停采，保护 12V 电瓶与电池），而 Tesla Streaming API 在车辆处于"行驶/充电"等活跃状态时 建立 WebSocket，推送秒级高频遥测（车速、功率、海拔、胎压等），从而在数据精度与续航之间取得平衡。地理围栏引擎 （geofences）会把原始 GPS 坐标自动翻译为可读地址，并识别"到家/到公司"等事件。

3核心创新点

TeslaMate 的价值，在于把"车企黑箱"打开，让车主第一次真正拥有自己的车载数据。

① 数据主权（Data Ownership）

区别于 TeslaFi 等 SaaS，TeslaMate 把每一字节的数据写入你自己的 Postgres。不存在第三方留存、不会被订阅到期清空、可完整导出与离线分析——这是隐私与长期价值的根本差异。

② Elixir/OTP 的高容错采集

选择 BEAM 而非 Python/Node，让"7×24 常驻拉取、车辆随机上下线、网络抖动"这种场景天然被 Supervisor 树与"let it crash"哲学兜住，长期运行稳定可靠，是同类项目少见的工程取舍。

③ 顶级的开箱 Grafana 看板

社区公认其预置看板是同类最佳：单次行程能耗拆解、充电曲线、电池衰减趋势、年度驾驶报告、"终身驾驶地图"（lifetime map）等一应俱全，部署即用，无需自行拼图。

④ MQTT → 智能家居闭环

实时把车辆状态（位置、锁、充电、里程）发布到 MQTT broker，可触发 Home Assistant 自动化："到家自动开灯开空调""离开自动布防""电量低于阈值提醒"，把车变成智能家庭的传感器。

⑤ 地理围栏自动归因

内置 geofencing 引擎，将原始 GPS 流自动识别为"行程起点/终点地址"，并标注常去地点（家、公司、充电站），让行程与充电记录天然结构化、可报销、可统计。

⑥ 睡眠友好的采集策略

智能判断车辆休眠状态，在车辆闲置时主动暂停轮询，避免持续唤醒导致电池涓流损耗与 12V 电瓶亏电——这是"懂特斯拉"的设计，远胜粗暴高频轮询的方案。

4应用场景

凡是"想对爱车有更细、更久、更自主洞察"的车主，都是 TeslaMate 的目标用户。

  • 个人用车分析：每段行程的能耗、效率、耗时、路线回放，量化"怎么开最省电"。
  • 电池健康/衰减追踪：长期记录可用容量曲线，判断电池衰减趋势，作为维保与质保依据。
  • 充电成本核算：自动关联电价，按充电会话统计费用，区分家充/超充成本。
  • 智能家居自动化：经 MQTT 接入 Home Assistant，实现到/离家、充电完成等联动。
  • 商务/报销里程：地理围栏自动归档行程起止点，生成可报销的行驶日志。
  • Homelab / 数据极客：作为 self-hosted 折腾项目，与 NAS、Proxmox、家庭仪表盘集成。
  • 车队/多人车数据：单实例支持多车，小型车队或家庭多辆特斯拉统一记录。
  • 二次开发数据源：经 TeslaMateApi (Go) 或直连 Postgres，喂给自定义应用、ABRP 续航规划。

典型采用画像：核心用户是技术型特斯拉车主、homelab 玩家、数据极客与智能家居爱好者， 他们通常已拥有 NAS（群晖/威联通）、树莓派或一台常开的小服务器，习惯用 Docker 部署、用 Home Assistant 管理家庭。在欧美、北欧与 中文 homelab 社区都有活跃讨论，是"汽车 + 自托管"交叉领域最具代表性的项目之一。

✅ TeslaMate 仍胜出的领域

  • 数据主权 100%，隐私与长期价值最佳
  • Grafana 看板美观、灵活、可深度自定义
  • 原生 MQTT → 智能家居自动化首选
  • 开源免费，可二次开发、可接 ABRP 等生态

⚠️ TeslaMate 的短板

  • 需自备服务器 + Docker 基础，门槛偏高
  • 强依赖特斯拉非官方 API，存在被改协议风险
  • 原作者已淡出，社区接棒，节奏不及商业产品
  • 仅面向特斯拉，不覆盖其他品牌

📈 市场趋势判断

  • 数据主权/隐私意识上升，自托管需求走强
  • Tesla 推 Fleet API，正逐步正规化第三方接入
  • 智能家居（HA）普及放大 MQTT 价值
  • 需关注 API 政策变动带来的维护成本
