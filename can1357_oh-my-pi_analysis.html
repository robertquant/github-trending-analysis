项目概述

oh-my-pi 是由安全研究员 Can Boluk（can1357）开发的开源终端 AI 编程代理。它基于 Pi agent harness 构建，是一个"batteries-included"的增强版本，旨在为开发者提供一种极简、高效且高度可定制的 AI 辅助编程体验。

与传统的 IDE 插件式 AI 工具不同，oh-my-pi 坚持纯粹的终端哲学——通过命令行界面实现完整的 AI 代理功能，包括代码编辑、文件搜索、LSP 语言服务、浏览器集成、子代理调度等。

核心理念：让 AI 的代码编辑"一次命中"——通过内容哈希锚定（hash-anchored edits）替代传统的行号定位，从根本上解决了 AI 编辑中常见的空白符冲突、字符串匹配失败等问题。

技术架构

oh-my-pi 的架构围绕"优化工具利用"（Optimized Tool Harness）展开，核心由以下几个模块组成：

1. Hash-Anchored Edits（哈希锚定编辑）

这是 oh-my-pi 最核心的技术创新。传统 AI 代码编辑器通过行号或精确字符串匹配来定位编辑位置，这容易因空白符差异、缩进不匹配等原因导致编辑失败。oh-my-pi 的方案是：

  • 为文件中的每一行/代码块计算内容哈希作为唯一标识符
  • LLM 不再需要重新输出要修改的行，只需引用哈希锚并提供替换内容
  • 从根本上消除了空白符战争（whitespace battles）和字符串未找到（string-not-found）错误
  • 显著减少 token 消耗——模型只输出锚点引用 + 新内容，而非重述整个上下文

2. 智能文件读取（Smart File Reads）

oh-my-pi 的文件读取不是简单地将文件内容原样输出，而是智能摘要——总结文件内容而非直接 dump，使 LLM 能更高效地理解代码库。

3. 瞬时搜索（Instant Search）

内置优化的搜索工具，支持代码级语义搜索，返回结果速度快且精准。

4. 持久化记忆系统（Persistent Memory）

oh-my-pi 实现了跨会话的记忆管理：

  • retain：在运行过程中写入事实/记忆
  • recall：在会话开始时检索存储的记忆
  • reflect：让代理对自身知识进行反思
  • 会话压缩：将每次会话压缩为精炼的知识模型，在下次会话首轮即加载

5. 子代理系统（Subagents）

支持生成子代理处理复杂任务，实现任务的并行分解和调度。

6. 多模型支持

兼容 Claude、GPT、Gemini、DeepSeek 等主流模型，也支持本地部署的开源模型。通过自定义 models.yml 配置即可接入新模型。

核心创新点

1. Hash-Anchored Edits — 解决 AI 编辑的可靠性难题

这是 oh-my-pi 对 AI 编程领域的最大贡献。在 AI 代码编辑场景中，最大的痛点之一就是 AI 生成的 diff/patch 无法正确应用——行号偏移、空白符不匹配、编码差异等问题导致大量编辑失败。oh-my-pi 的哈希锚定方案从根本上解决了这个问题。

社区反馈：Pi 原始维护者 Mario Zechner 亲自验证，使用哈希行方案完成了约 1,300 次编辑，证明了该方案的实际可靠性。

2. Token 效率优化

通过锚点引用替代全文重述，大幅降低了每次编辑的 token 消耗。在长会话和大规模代码库编辑场景下，token 节省尤为显著。

3. 极致可定制性

社区评价 oh-my-pi 为"extremely hackable with sensible defaults"——可以禁用不需要的组件，接入自定义认证、子代理、MCP 服务器等。这种"合理的默认值 + 深度可定制"的设计哲学使其既适合新手快速上手，也满足高级用户的定制需求。

4. 安全研究者视角的系统设计

作者 Can Bolük 的安全研究背景体现在项目的多个层面：精确的编辑机制、对可靠性的极致追求、以及对系统行为的可预测性。这使得 oh-my-pi 在同类工具中具有独特的工程品质。
